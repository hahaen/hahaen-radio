# 正式环境部署

## 需求与范围

通过现有 Jenkins 手动发布到已有 HTTPS 网关的 `/radio/`，正式库使用同实例中的独立 `ha_radio`，开发库继续为 `ha_radio_dev`。

## 实际变更

- 增加前端构建路径配置，统一路由、API、地理资源和许可链接前缀。
- 目标发布支持已有网关后的回环 HTTP 模式，保留版本绑定、维护、备份、Drizzle Kit 迁移及 API → Web → 任务验收顺序。
- Web 镜像记录构建路径，发布时核对，避免页面成功但资源或接口路径错配。
- CI 检出采用严格 umask；镜像复制时显式将迁移源材料、Web 静态资源与配置交给镜像运行用户，避免普通用户读取权限依赖开发机文件模式。
- 已只读核对目标 Ubuntu、Docker、MySQL 与 Jenkins；正式空库、独立 TLS 身份、两个专用节点及私有回环镜像仓库已完成配置，镜像拉取身份只读访问已验证。真实配置只保存在受控私有位置。

## Review 与验证

本次改动已人工 Review 路径解析、根路径兼容、接口前缀、代理边界与私有配置约束；修复了工具类型检查的模块扩展名及可选字段问题，并复审通过。27 项相关测试、TypeScript、ESLint、格式和文档链接检查通过，`/radio/` 生产构建与资源预算通过；生成 HTML、CSS 已核对资源前缀。目标 Jenkins Declarative Linter、MySQL 证书和主机名校验通过，网关配置与持久网络配置检查通过。CI 普通测试限制为一个 worker，四核构建节点的浏览器回归使用两个 worker。正式容器验收和发布结果将在实际执行后补充。未执行的操作不计为已部署。

## 实际部署配置与后续发布入口

- Jenkins 文件夹显示名为「声屿 HAEN」，路径为 `radio`，任务为 `radio/haen-radio`；采用 SCM 中的根 Jenkinsfile，保留手动触发与两次分发/目标审批。
- 构建和目标使用两个专用、单执行器节点；目标配置通过 `HAEN_DEPLOY_ENV_FILE` 显式加载，构建节点不加载数据库配置。
- 私有镜像仓库只绑定宿主机回环地址，使用 TLS；分发与拉取使用不同 Secret file，已实际验证拉取身份不能执行上传请求。
- Web 复用已有 HTTPS 网关，剥除 `/radio/` 后访问 Caddy；正式服务为 Web、API 和一个任务进程。已有网关和数据库的外部网络声明已持久化，没有重启已有 MySQL 服务。
- 生产连接保留可信 CA 和主机名校验；已用正式发布身份、应用驱动完成连接验证，并在只读预检中实际核对本机文件锁、数据库发布锁及空库状态。
- 已准备固定版本的受控运维包、原生 MySQL 客户端和最小 sudo helper；真实配置不放在工作区、镜像、普通文档或产物归档中。

后续在任务的 **Build with Parameters** 中填写完整 `SOURCE_COMMIT`，按需勾选 `PUBLISH_IMAGES` 和 `DEPLOY_TARGET`，一般选择 `DEPLOY_SCOPE=full`。镜像与目标审批通过后才更新服务；只构建或只上传镜像不等于上线。首次初始化完成后，不再勾选空库初始化和首次目录同步选项。分端更新需确认保留一端的接口与结构兼容。

用户已确认目前没有独立备份存储，先完成首次空库上线。因此未配置 `BACKUP_REPLICA_DIRECTORY`，未启用需要该副本位置的每日备份定时器；后续存在数据库结构升级前必须先补齐独立副本配置和校验。无待执行迁移的普通发布沿用现有升级流程，不要求手动复制 SQL。

## 原生浏览器环境修复

Firefox 最小受控 MP3 复现返回 `MEDIA_ERR_DECODE / OnMediaSinkAudioError`，系统解码库已存在；为构建身份建立隔离 PulseAudio null sink 后，同一复现转为 `playing`，原先超时的中文可访问性用例在 22.3 秒通过。该修复仅作用于构建节点，不改变产品音频代码或生产浏览器行为。既有浏览器回归用例覆盖此实际故障，无需增加浅层模拟测试；临时探针保存在私有调试位置，交付前清理。
