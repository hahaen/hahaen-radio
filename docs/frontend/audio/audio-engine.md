# 音频引擎

## 技术基础

已实现 HTMLAudioElement 播放、原生 HLS 检测和按需加载 hls.js 1.7.3。源码位于 `apps/web/src/audio/engine.ts`、`hls-adapter.ts` 和 `controller.ts`。Web Audio 分析及 Media Session 属于后续阶段，当前没有将音源强制接入分析链路。

音频引擎作为独立 TypeScript 模块，不依赖 React。由应用服务持有播放器生命周期，界面通过命令和事件交互。

## 播放状态

状态为 idle、connecting、playing、buffering、paused、blocked 和 failed。playing 依据实际媒体事件；play Promise 返回不等于已播放。blocked 保留当前线路并要求用户再次点击，不能把手势限制当作坏线路连续重试。

快速更换音源时使旧任务失效，清理旧 HLS 实例和事件，避免旧连接的回调覆盖新播放状态。连接超时、重试和备用源切换设置有限次数与总耗时。

每条线路连接或持续缓冲上限 8 秒，每台最多 3 条；同台候选用尽后，未固定且仍有播放意图时最多自动选择 2 个其他电台。本轮失败 ID 被排除，防止 A/B 来回重试；没有其他候选时停止，等待显式操作。固定状态阻止自动换台，显式选台、上一站和下一站仍可操作。

每次尝试创建独立媒体元素，切换时移除旧监听、计时器、HLS 会话和 src，再清理元素。HLS 保留最多约 30 秒前向缓冲、不保留后向缓冲，网络重试受加载策略及引擎时限约束。暂停会停止加载；初始清单若在暂停中被取消，恢复时重新请求清单，不能只调用 startLoad 后等到超时。

暂停发生在详情请求完成之前时，后续响应只能更新选中台，不能擅自播放。系统暂停视为停止播放意图；断网终止尝试，恢复网络后需显式重试。音量和静音跨换台保留，设备不接受音量赋值时提示使用系统音量键。

## 网络路径与跨域

默认由浏览器直连音频服务，API 只提供播放信息。客户端的网络可达性、TLS、混合内容限制、编码与跨域响应共同影响结果。

普通媒体播放可用不代表 Web Audio 可以读取音频。跨域分析路径必须验证源站许可；不能盲目将所有音源接入分析链路，避免将可播放音源变成静音。分析不可用时使用基础播放路径，界面如实表示能力。

## 浏览器生命周期

- 首次播放和 AudioContext 恢复处理用户手势要求。
- 处理 `play()` Promise 拒绝，不将调用成功等同于已播放。
- 移动端后台播放、锁屏控制、音量设置和系统中断需要真实设备验证。
- 定时行为使用截止时间判断，考虑后台节流；浏览器挂起期间无法保证准点执行。
- 退出或销毁时清理媒体、HLS、AudioNode 和事件监听器。

## 验证范围

使用可控测试音源验证状态转换和错误分支，再验证实际音源。区分传输问题、浏览器策略、编码问题和分析权限问题。

可控 MP3/AAC/HLS 样例均为项目生成的短测试音。三浏览器及手机模拟视口验证媒体 playing、时间持续推进、error 为空、暂停恢复和旧回调失效，不用模拟 playing 事件代替浏览器解码。真实电台观测另行归档；来源检查通过不代表任意浏览器网络都能播放，服务端响应成功也不能证明浏览器请求不会遇到 403。

代理、转码或外部识别服务的接入不属于已实现能力，应另行确定调用路径和资源预算。
