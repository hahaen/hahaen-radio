# 容器拓扑与持久存储

## 服务组织

| 服务 | 镜像与职责 | 数据访问 |
| --- | --- | --- |
| `web` | Caddy 2，镜像内包含前端构建产物 | 读取静态文件、保存证书状态 |
| `api` | Node.js 24 Debian slim，运行 Fastify | 读写 SQLite 持久卷 |
| `jobs` | 与 API 相同的服务端镜像，使用任务入口 | 读写同一个 SQLite 持久卷 |
| 迁移入口 | 服务端同版本镜像的一次性进程 | 发布维护阶段单次访问数据库 |

前端独立部署通过更新 `web` 镜像完成；后台独立部署需要协调 `api`、`jobs` 和数据库版本。具体镜像名称、注册表、端口和卷名称在目标环境确认后配置。

## 路由和网络

只向外暴露 Web 入口所需端口。API 通过 Compose 内部网络访问；数据库采用文件访问方式，不开放数据库网络端口。

Caddy 对 `/api/*` 代理并保留路径前缀。前端路由回退只用于页面请求，不能将不存在的 API 或静态资源错误回退为 HTML 成功页。

前端带哈希资源使用长期缓存，HTML 使用更新可见的缓存策略。Caddy 证书申请需要域名、DNS 和验证端口满足实际部署条件，证书状态持久保存。

## 持久存储

| 内容 | 规则 |
| --- | --- |
| SQLite 数据库及相关文件 | 本机持久目录，API 与任务挂载相同卷 |
| 备份 | 独立目录，并有独立存储位置副本 |
| Caddy 状态 | 持久卷保存证书与必要状态 |
| 运行配置 | 由环境文件或受控挂载注入 |

发布保留持久卷，禁止将清理数据库卷作为例行更新步骤。数据库文件不随前端构建、镜像打包或工作区清理覆盖。

## 构建

使用多阶段 Docker 构建，分别产生 Web 和服务端镜像。安装原生模块的环境与最终运行环境保持架构、系统库和 Node.js ABI 兼容。

镜像使用提交标识或发布标识形成不可变版本，运行配置记录具体版本。全新机器构建和目标服务器启动均属于上线前验证内容。
