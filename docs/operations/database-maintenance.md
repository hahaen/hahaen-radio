# 数据库维护协调

备份创建与迁移入口已共用 MySQL 会话级维护锁，协调访问同一实例、同一项目库的不同进程和运维节点。锁名由固定命名空间与库名 SHA256 前 40 位构成，长度小于 MySQL 的 64 字符限制；不会因主机别名、备份目录或发布任务不同而改变。

## 入口与执行顺序

- `pnpm db:backup create ...` 在备份目录互斥之外取得数据库维护锁，持有到导出、完整校验及清理结束。
- `pnpm db:migrate` 及迁移镜像入口在启动 Drizzle Kit 前取得同一锁，持有到工具退出；遇到占用立即失败，不排队或自动重试。
- verify、prune 只操作备份文件，不占用数据库锁；隔离恢复使用全新测试库，不改变源库。

迁移前先停止 API、任务及其他写入方，等待连接关闭，按备份说明生成并校验迁移前备份。确认后在迁移专用私有配置中设置 `MIGRATION_WRITES_STOPPED=true`；入口缺少该确认会在连接数据库之前拒绝。该值声明操作者已经完成停写，不会自动停止其他程序。首次初始化也必须确认没有写入方；目标空库由受控步骤预先创建。

备份身份、迁移身份相互独立。每个维护命令另占用 1 条专用锁连接，备份还使用元数据连接和原生客户端连接，应计入实例连接预算。锁连接实际校验 MySQL 8.0.46、utf8mb4_general_ci、UTC 及 TLS；不创建业务表、租约表或新的迁移机制。

## 取消与失败

锁连接每秒检查所有权，单次检查超时 3 秒；断线、失去所有权或检查失败会取消工具。迁移工具最长运行 120 秒，收到取消先发 TERM，2 秒仍未退出则发 KILL，等待真实 close 后才清理并尝试释放锁。备份沿用 5 分钟客户端期限，并将失锁信号传递给导出及文件管线。原始客户端输出、SQL 和配置值不写入普通日志。

这些机制不撤销已经提交的 SQL。MySQL 可能继续完成已提交的 DDL，网络异常、强杀父进程或实例重启也不能证明所有旧会话已停止。失败后保持维护窗口，核对进程、连接、实际结构、迁移历史和备份，再决定下一步；禁止仅因锁已空闲就自动重试。

## 发布协调边界

锁为协作式互斥，只约束采用本入口的命令，不能阻止直接调用 Drizzle Kit、客户端 DDL、其他软件或管理员操作。生产禁止绕过入口。它只在一个 MySQL 实例内有效；数据库代理必须把锁连接与操作连接路由至同一主实例，不适用于会话漂移、多主或 NDB 全局协调。

备份与迁移分别持锁，中间不是一个原子发布事务。完整发布仍需外层按目标数据库共享的 Jenkins 发布锁，覆盖停写、备份、迁移、更新和验收；其他调度也必须遵守维护窗口。每日执行与本机发布文件锁材料见[每日备份](daily-backups.md)，服务器启用和真实存储仍待验收；Jenkins 外层协调继续补齐，不把本模块视为完整发布系统。

## 验收入口

`pnpm test:backup` 使用全新隔离库，覆盖编译迁移入口的停写确认、锁占用拒绝、空库初始化与重复执行、备份锁占用拒绝，以及主动断开本轮锁会话后确认受控子进程已退出。测试只终止本轮拥有的锁连接，不处理其他会话；仍包含备份副本恢复与应用就绪验收。

该测试身份需要在其专用测试库内执行 DDL，以及终止其自身身份的测试会话；普通业务身份无需该权限。生产维护锁不执行 KILL CONNECTION。

机制依据见 [MySQL GET_LOCK](https://dev.mysql.com/doc/refman/8.0/en/locking-functions.html)。返回[运维导航](README.md)、[迁移流程](../data/migrations/workflow.md)或[备份操作](../data/backup/backup-and-restore.md)。
