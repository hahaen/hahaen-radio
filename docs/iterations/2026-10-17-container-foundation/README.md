# 容器交付基础

## 需求与实现

实现 Web、服务端、独立迁移三个镜像目标，生产 Compose 和 Caddy 同域静态/API 路由；服务端以独立生产包运行编译入口，迁移保留完整工具材料。增加构建上下文排除、分角色私有环境注入、强制生产 TLS、持久状态与限额临时目录。没有执行目标数据库迁移或正式部署。

## Review 与验证

范围仅包含本轮 Dockerfile、Compose、Caddy、生产包 files 配置、相关导航与文档。Review 核对源码/工具依赖边界、运行时配置注入、非 root 权限、持久卷、API 路径、静态错误与 HTML 回退、兼容窗口和凭据排除。已修正未知扩展名资源回退与 API 响应缓存覆盖边界。实际 Caddy 验证还发现通用 no-cache 覆盖哈希资源缓存，已改为现存 assets 的延迟写入，并让缺失资源保持非长期缓存；修复后复审路由及响应头顺序。另在非 root Web 构建中移除基础二进制的低端口 capability，以配合内部高端口及 cap_drop=ALL；其 Linux 实际执行仍随容器补测。

基础镜像由官方 registry 的 manifest 内容与 SHA256 交叉核对，两个镜像均包含 linux/amd64 和 linux/arm64。Python 默认信任库无法验证 registry TLS；改用本机 Node 可信 TLS 请求成功，没有关闭证书校验。

本机 macOS arm64 的干净临时检出通过冻结安装、格式、Lint、类型、164 项普通测试及生产构建；10 项 MySQL 用例按设计跳过，本轮没有数据库改动或写入。独立 pnpm 生产包已逐项检查符号链接不逃逸产物、不含服务端 src、tsx 或 Drizzle Kit；迁移工作区中的配置、Schema、SQL、编译入口与固定 CLI 均存在。

生产入口在缺少数据库配置时退出失败，未伪装为可用；随后独立生产包在 test 模式、未配置数据库条件下真实启动，live 为 200、ready 为 503、显式关闭的文档接口为 404。未放宽生产数据库或 TLS 检查。

官方独立 Compose 2.30.3 工具通过配置解析和静默校验，检查 raw 环境文件、生产库名/TLS 覆盖、只读根文件系统、单个 tmpfs 挂载、CA 只读绑定、服务端无公开端口及手动迁移 profile；缺少必填镜像时拒绝。只使用合成环境值，未连接 Docker 守护进程或数据库。规范化输出会转义美元符号并省略 false，辅助断言已按实际输出修正，不把 JSON 展示转义当作运行时注入结果。

官方 Caddy 2.10.2 macOS 工具通过发布方 SHA512 校验，配置 validate/adapt 与真实 HTTP 代理检查通过：API 前缀与 JSON 404、精简报告 POST、缺失资源 404、HTML GET 导航回退、非导航 POST 拒绝、哈希资源及 API 缓存策略。测试只替换静态根目录、API 上游与 loopback 端口，使用 test 模式 API；不代表 Linux 容器、公开 HTTPS、数据库 TLS 或实际网络部署验收。临时子进程已退出，临时检出与本轮产生的本机工具状态已清理；后续原生验证的状态限定在临时目录。

工具结果、基础镜像与配置 SHA256 见[结构化证据](results.json)。按用户明确要求不安装 Docker、不执行本机镜像或容器验收；该项延期至实际部署环境。

同步 upstream 无新增提交，20 个本轮文件（含占位文件删除）的内容、权限和暂存区完整恢复。同步后仅复审本轮差异，再次通过干净检出完整检查、独立包与原生代理、Compose 配置验证，以及 Drizzle Kit check；没有迁移写入。复验子进程均已退出，临时检出已删除。文档链接与差异检查通过。
