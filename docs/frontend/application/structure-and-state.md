# 应用结构与状态

## 应用组织

使用 React、TypeScript、Vite 和 React Router。应用入口统一安装路由、查询客户端和国际化 Provider。按职责拆分业务模块，共用 UI 组件放入独立目录。

## 状态归属

| 数据类型 | 管理位置 | 规则 |
| --- | --- | --- |
| 单个组件的临时交互 | React 局部状态 | 保持局部 |
| 跨组件界面状态 | Zustand | 通过选择器订阅需要的字段 |
| 后端数据与请求状态 | TanStack Query | 使用稳定 Query Key，显式失效 |
| 可分享、可导航状态 | URL | 解析和序列化统一封装 |
| 高频图形数据 | Three.js 引擎内部 | 不逐帧写入 React Store |
| 播放器内部状态 | 音频引擎 | 通过事件向 UI 报告 |

服务端数据不在 Zustand 中再维护一套独立缓存。URL 和本地偏好存在冲突时，由具体模块明确优先级。

场景目录通过 TanStack Query 读取，IndexedDB 仅保存两个完整版本；完整目录就绪后搜索、场景和随机入口共用候选集合，就绪前列表使用分页 API。当前电台列表按查询词和分页建立 Query Key，播放协调器采用 Zustand vanilla Store 保存选中台、播放意图、实际状态和固定状态。音频资源由独立 AudioEngine 持有，React 通过订阅更新；详情请求使用取消令牌，不能让旧响应覆盖新选择。上一站导航从最近 100 台成功收听 ID 初始化，详情按需获取；刷新或分享恢复保持暂停，上一站继承当前播放意图。未登录时电台收藏、恢复项和筛选继续本地持久化；登录后编辑草稿由现有收听 Store 管理，同步协调器使用账号版本合并与写入，不另建目录缓存；筛选和设置保持本地，详见[个人收听工具](listening-tools.md)。设置、截止时间与系统媒体见[收听设置](listening-controls.md)。

组件生命周期重放会清理并重新建立引擎订阅，不自动恢复声音；页面后台隐藏不会主动销毁播放器。播放器实际高度由 ResizeObserver 写入布局变量，单屏主体底部预留同等空间和安全区。页面使用动态视口高度并禁止文档滚动；电脑保持左右构图，手机在可用高度内纵向分配场景与当前电台信息。搜索目录由顶栏入口或 `/` 快捷键打开模态弹层，选台后关闭；地点列表同样使用模态弹层，保留内部滚动、Escape 关闭与焦点恢复。较长电台信息在独立区域内部滚动。

曲目状态通过带电台与线路 ID 的独立查询缓存读取，仅在实际播放时轮询；旧身份结果不能覆盖新选择。歌词在用户操作后读取，版本、手动校时与跟随状态由曲目组件管理，四分之一秒更新仅作用于歌词区域，不逐帧刷新应用。详见[曲目与歌词](tracks-and-lyrics.md)。

## 请求与契约

统一 Fetch 封装负责请求路径、超时、AbortSignal、响应校验和错误转换。页面卸载和查询取消能够中止请求；只对适合重试的读请求配置有限重试。

前后端共享 `contracts` 中的 Zod Schema 和 DTO。TypeScript 类型不能代替外部数据的运行时校验。

## 样式与基础组件

界面遵循已确认的[夜航设计规范](../design/night-voyage.md)。颜色、字体、间距、圆角、动效和响应式构图以该文档为统一基线，概念图中的示例数据和控件不自动成为功能需求。

CSS Modules 管理组件样式，CSS Variables 管理颜色、字体、间距、圆角和层级。Radix UI 提供基础交互，Lucide React 提供图标。

字体和必要资源随构建分发；字体选择时确认字体格式、中文覆盖和使用许可。常规动画使用 CSS，尊重减少动态效果的系统设置。

## 国际化与交互约定

文案统一进入 i18next 语言资源，组件不拼接依赖特定语言顺序的句子。弹层管理焦点，控件具有可访问名称；全局快捷键避开文本输入、组合输入和浏览器保留组合。
