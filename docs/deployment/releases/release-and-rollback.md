# 发布与回退

## 发布单位

Web、服务端与迁移工具镜像分别构建，来自同一确定提交。服务端镜像供 API 和任务使用；迁移镜像保留固定版本 Drizzle Kit、mysql2、配置、SQL 和元数据。完整发布记录镜像组合、MySQL 目标和数据库迁移版本。

默认由 Jenkins 协调一起发布。前端可以单独更新，后端可以在接口兼容且数据库状态匹配时单独更新。

## 无数据库迁移的发布

1. 检查构建结果、当前运行版本和目标镜像。
2. 确认前后端契约兼容，按范围更新服务。
3. 检查健康、页面资源、接口与日志。
4. 保存发布记录，验收失败时回退到兼容的上一镜像组合。

## 有数据库迁移的发布

1. 完成构建与镜像分发，确认迁移已在独立 MySQL 8.0.46 空库和含旧结构数据的测试库验证。
2. 进入维护窗口，停止任务和 API 写入，等待连接关闭。
3. 生成并校验数据库备份，记录对应版本。
4. 用同一提交的迁移工具镜像调用 Drizzle Kit，单次执行已审核迁移，不在发布时生成 SQL。
5. 先启动新 API 并完成数据库与契约检查，再启用匹配的 Web 资源。
6. 检查任务兼容性，恢复一个任务进程，再结束维护状态。
7. 记录迁移实际执行状态和应用验收结果。

维护窗口和更新顺序已接入[目标执行器](target-executor.md)，真实 Linux/Docker 流程待部署环境演练；当前单机方案不承诺无中断发布。

## 回退边界

| 情况 | 处理原则 |
| --- | --- |
| 前端构建或资源异常 | 回退 Web 镜像，确认 API 仍兼容 |
| 后端异常、数据库未变 | 回退兼容服务端镜像，协调任务版本 |
| 数据库迁移已执行 | 先判断旧代码能否运行在新结构上 |
| 迁移部分失败或结构不兼容 | 保持维护状态，检查迁移结果并决定修复或恢复 |
| 需要恢复旧数据库 | 明确恢复点及后续数据影响，执行已验证的恢复流程 |

MySQL DDL 可能隐式提交，迁移失败后必须核对实际结构与迁移记录，不能无条件重跑。镜像回退不会自动回滚数据库。禁止用未经验证的逆向 SQL 或直接删除数据库来处理发布失败。

## 发布报告

至少包含目标环境、域名或服务名、提交、镜像、配置变更、SQL 准备和执行情况、发布顺序、验收结果及遗留问题。不能把“镜像启动成功”表述为全部业务已验收。

备份与恢复见[数据文档](../../data/backup/backup-and-restore.md)。返回[部署导航](../README.md)。
