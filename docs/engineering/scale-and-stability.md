# 大目录与连续切换验收

该验收覆盖客户端完整目录加载、搜索筛选、缓存与短时资源趋势。可控数据与真实服务观测分开，不将合成数据的速度视为真实网络或手机性能承诺。

## 可重复入口

```sh
pnpm test:e2e tests/e2e/stability.spec.ts
```

用例在独立浏览器上下文注入 30000 条有坐标的合成电台、30 个每片 1000 条的目录分片和本地 MP3 测试音源。生产应用不包含这些默认数据，也不修改开发或正式目录。加载应完成全部分片，不为每条电台单独读取详情；搜索末尾记录、筛选一半目录并恢复全部后，交替收听两个电台和切换地球/流派 60 轮。抽样检查实际媒体时钟前进、一个音频元素和一个地球画布；暂停后不继续请求音源，刷新应复用完整 IndexedDB 分片。

记录首次加载、搜索和筛选的本机经过时间；它们包含开发服务器、自动化等待与调度开销，不能作为生产接口延迟。首次加载须在 30 秒的本机回归窗口内完成。实际 API 的规模查询、外网播放及移动设备帧率另验。

## 资源观测与阈值

第 10、30、60 轮分别取样。Chromium 桌面与移动模拟使用 CDP 请求 GC 后读取 JS 堆、包含保留节点的 Nodes 及事件监听器数量；Firefox/WebKit 只记录当前 DOM 数量，不将其描述为完整内存检查。

本机回归阈值为第 60 轮相对热身后第 10 轮：JS 堆增量小于 10MiB、节点增量小于 200、监听器增量小于 100。在 60 轮结束、刷新前，媒体请求总数不超过 122（WebKit 每次播放先探测 0–1 字节，再读取音源，共 61×2 次）、详情请求不超过 61（初始播放一次加切换 60 次），防止有限切换演变为持续请求。阈值用于捕获明显增长，不能证明长期无泄漏、GPU 资源已完全回收或任意设备达到固定帧率。使用重复的两个电台，是为了将合法详情缓存增长与反复创建后未释放的资源分开。

附件的 counts 包含最后刷新产生的恢复查询；样本中的 media/details 为对应轮次计数，阈值在刷新前检查。

每个项目输出 `scale-and-stability.json` 附件，记录样本、请求计数与页面异常；失败时保留 Playwright 截图和 trace。具体运行结果见[阶段记录](../iterations/2026-10-17-scale-stability/README.md)。
