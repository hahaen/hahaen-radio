# ADR-0003：建表选项与实际目标环境

日期：2026-10-16。状态：已接受规范，应用与迁移实现待验证。修订 [ADR-0002](0002-mysql-and-drizzle-kit.md) 的版本基线与通用字符配置，其余工具分工不变。

## 背景与证据

用户要求重点统一字符集、排序规则和存储选项。本次经本机数据库工具只读读取元数据，确认实际目标版本是 MySQL 8.0.46，参照库与全部 18 张表采用 utf8mb4_general_ci、InnoDB 和 Dynamic 行格式，部分字符列使用 ascii_bin。

开发与正式目标库名已经指定，检查时尚不存在。没有读取业务记录、创建数据库、修改连接安全设置或执行结构迁移。

## 决定

1. 库和业务表默认显式使用 `utf8mb4`、`utf8mb4_general_ci`；表使用 `InnoDB`、`ROW_FORMAT=DYNAMIC`。
2. 对大小写敏感的机器标识按值域定义字段级字符集与排序规则，保留 ASCII 字段的 `ascii_bin` 例外，不统一覆盖所有列。
3. mysql2 会话配置与迁移 SQL 均检查这些规则，既有表的排序规则变化按正式迁移验收。
4. 环境固定映射开发 `ha_radio_dev`、正式 `ha_radio`，启动和运维入口显式核对 `DB_NAME`。
5. 当前实现与隔离测试匹配实际目标 MySQL 8.0.46。原 8.4 LTS 作为先前设计记录保留，不视为服务器已经升级，也不自动升级既有服务。
6. Drizzle Kit 继续作为唯一迁移执行工具；本次只建立规范，不生成或执行建库建表 SQL。

## 影响与验证状态

更新当前技术文档中的版本目标，保留历史决策与历史归档。元数据读取成功不等于应用连接、迁移、性能和备份恢复均已验收；应用端 TLS 链路仍需单独验证。

详细结果与规则见[建库建表选项](../../data/database/table-options-and-collations.md)。
