# Safari 深色耳机图标

日期：2026-10-24。

## 需求与实际变更

iPhone Safari 分享面板原来显示白色图标底，要求与 Android App 的深色耳机图标一致。检查实际 HTML 声明的 Apple Touch PNG，180px 资源四角 alpha 均为 0，旧应用图标也未绘入背景。新图标直接提供完整深色底，不依赖系统为透明部分选择颜色。

- 180px Apple Touch Icon 与 192px / 512px 清单图标统一使用 Android 的 `ic_launcher_artwork.png` 和 `#0B2019` 背景，输出为不透明 RGB PNG。
- 依据 Android 108dp 图层、左右 16%、顶部 18.5%、底部 13.5% 的 inset，将中央 72dp 区域映射到方形图标：原图缩放为目标边长的 1.02 倍，左偏移为 -1%，顶偏移为 2.75%，导出时按像素取整；耳机、太阳与海浪的比例及配色来自原图。
- 图标更新为 v2 文件名，清单入口增加 `v=2` 参数，保持 Vite 根路径及 `/radio/` 子路径支持。保留旧 v1 文件供旧页面读取，新页面只声明 v2。
- HTML 明确声明 512px 深色图为 `og:image` 并提供宽高。仅替换 Apple Touch Icon 时，已测 Safari 仍把小图标放进白色底框；独立预览图片入口解决这一实际分享面板问题。
- 标签页的透明 PNG / ICO 和播放动效沿用现状；构建仅分发已导出的图标，不依赖 Android 构建或图片处理工具。

生成使用一次性的 Pillow 工具环境：`uv run --with pillow python`；不向前端添加图片处理依赖。系统外轮廓由平台处理，未预先裁切圆角，也未声明 `maskable`。

## Review 与验证

Review 范围限定为本轮图标、HTML / 清单入口及必要文档，不包含工作区已有的网页音频修改。已核对原图来源、主体比例、背景不透明度、版本引用、子路径、旧资源兼容及构建边界，无未解决问题。原始资源检查已复现：旧声明资源四角为 `(0, 0, 0, 0)`，不满足不透明深色背景要求。

- HTTP 获取实际声明的 180px 图标及清单内 192px / 512px 图标，尺寸正确、所有像素 alpha 为 255、四角为 `(11, 32, 25)`，响应字节与仓库资源一致；原始检查由失败转为通过。
- 真机 Safari 对照明确复现：只有不透明 Apple 图标时仍有白色外框；在同一 iPhone 的独立本地测试入口仅增加预览图片声明后，分享面板改为完整深色图块。限定资源请求观测确认实际读取 512px 深色预览图。预览元数据机制见 [Apple 富链接说明](https://developer.apple.com/videos/play/tech-talks/205/)。
- 最终源码的本地 HTTP 页面在同一真实 iPhone Safari 再次复验，分享缩略图为完整深色图块、耳机清晰、没有此前白色外框。截图仅存放在被 Git 排除的本机私有目录，权限 600。设备型号与系统版本本轮未采集，镜像截图为 628×1398 像素，不将其写成网页逻辑视口。
- 电脑端 Chrome 1496×738 视口核对实际 DOM：Apple 图标、清单与分享图片均指向 v2，分享宽高为 512，原有两个标签页图标声明保留。
- 前端 TypeScript、根路径生产构建、`/radio/` 生产构建、HTML / 清单 Prettier、文档链接及差异检查通过；构建保留既有大分块提示。两种产物内的图标和预览地址均按各自 base 路径解析，图片已复制到产物中。
- GitHub upstream 与 Gitee 同步均无新增提交，私有备份的 14 个既有及本轮文件指纹保持一致；同步后复审无新问题，复验最终构建、资源和文档。已有网页音频改动单独保留，未纳入本次图标提交。

分享面板与添加到主屏幕／程序坞分别验收，不将分享缩略图通过等同于全部系统入口通过。

## 同日追加：标签页图标统一

用户要求浏览器标题旁的图标也采用同款深色背景。将已确认的 512px 不透明应用图标等比导出为 32px PNG，以及含 16/32/48/64px 的 ICO，使用 `haen-favicon-v3` 新文件名。HTML 两个标签页声明、播放动效的图源及已有资源加载失败回归同步更新；旧 v1 / v2 文件保留，供旧缓存页面读取。播放、暂停、省电、减少动态效果与隐藏页面的动效规则不变。

Review 范围限定为新图标及三处引用、已有回归的路径和相关文档；已核对静态与动态图源一致、生命周期恢复及根路径／子路径支持，无未解决问题。此追加取代上文“标签页透明图标沿用现状”的历史边界。

验证：PNG 及 ICO 的 16/32/48/64px 图层均为不透明深墨绿底，PNG 像素与已确认应用图标的等比缩小结果一致；实际桌面 Chrome（窗口截图 2992×1718 像素）的标签栏已核对并取得私有截图。已有两项播放图标回归在 Chromium、Firefox、WebKit 与 Pixel 7 模拟共八项均取得通过结果：首轮并发七项通过，Chromium 动画首次等待超时，资源响应为 200；不改代码、不放宽断言的单 worker 定向复验两项通过，未将初次超时归因为确定的应用缺陷。前端 TypeScript 与生产构建、定向格式／ESLint、文档链接及差异检查通过；根路径与 `/radio/` 产物均引用 v3，保留既有大分块提示。手机为模拟验证，未追加真机专项。仅需更新 `radio-frontend` 静态资源，无 API、后台任务、数据库或配置变更；未执行发布。此前结束的设备专项不再继续。
