# 识曲配置与持久化额度

识曲默认关闭。当前不包含真实凭据申请、账户开通、订阅、充值或实际付费调用。测试配置不代表可用的供应商服务。

## 私有配置

| 变量 | 用途 |
| --- | --- |
| `RECOGNITION_ENABLED` | 默认 false；只有用户提供凭据与明确额度后才设为 true |
| `AUDD_API_TOKEN` | 仅服务端读取的供应商令牌，必填，无真实默认值 |
| `RECOGNITION_REQUEST_LIMIT` | 当前预算允许的最大上传次数，显式填写 1–100000；不自动补充 |
| `RECOGNITION_BUDGET_ID` | 人工授权的预算标识，1–64 位字母、数字、下划线或连字符 |
| `RECOGNITION_STATE_PATH` | 私有持久目录中额度文件的绝对路径，不放在前端静态目录或镜像层 |

只向 `.env.local` 填实际值，文件先确认已排除且未被 Git 跟踪，权限 600。API dev/start 与额度初始化命令均显式加载该文件；生产通过受控运行环境注入。启用时任何必填值缺失即报变量名，不打印输入值；关闭时不创建额度文件或锁。

当前方案只支持既定的单 API 实例。额度目录权限 700、文件 600，所有者必须是运行用户；目录与额度文件不接受符号链接。部署必须使用可写持久卷，不能使用每次重建即丢失的容器目录，也不能让多个实例以不同文件共享同一份授权预算。

## 首次启用

1. 从 `.env.example` 的空模板准备被排除的私有配置；向供应商核对有效令牌、计费规则及实际可用次数。其他程序使用同一令牌的消耗不在本应用计数内，宜使用独立令牌或扣除其他用途的预算。
2. 在目标运行用户下创建私有持久目录并设为 700，配置绝对状态路径。停止 API 后操作，保留既有文件。
3. 开发环境在仓库根执行 `pnpm recognition:quota init`。该命令只初始化私有额度，不调用供应商、不连接数据库，不覆盖既有文件。编译后的生产工具入口为 `node dist/entrypoints/recognition-quota.js init`，从服务端工作目录运行并由运行环境显式注入变量。
4. 启动 API，再更新 Web。查询 `/api/v1/capabilities` 核对状态；有效目录、额度与配置就绪才可用。
5. 首次真实识别由用户明确触发并记录供应商结果、实际扣次和剩余额度，不能用本地样例代替。

正常关闭先取消识曲任务，再等待请求退出并释放独占 `.lock`，不重置计数。重复清理不会删除后续实例持有的锁。重复初始化、修改既有预算 ID/上限、换令牌、文件损坏、权限过宽或另一个进程持有锁都会失败，不会静默产生新预算。

## 扣次、恢复与关闭

每次上传前，先把 used + 1 写入权限 600 的临时文件、同步文件、原子替换并同步目录，再发送供应商请求。网络失败、超时或取消后的不确定调用也保守保留已扣次数；采样失败且未开始预扣时不扣；在预扣过程中取消也可能保守保留一次。额度是应用的调用上限，不能替代供应商账单或账户级额度查询。

进程异常退出可能留下锁。先核对锁中 PID、进程身份、部署状态及没有其他 API 使用该路径，再由运维移除确认失效的锁；程序不自动抢占。状态损坏、持久卷丢失或从备份恢复时，停止识曲并核对供应商实际消耗；不能恢复旧计数来重复使用预算。新的授权额度必须由用户确认后另建预算及状态路径，旧记录留在受控私有资料中，不执行自动周期清零。

关闭时将 `RECOGNITION_ENABLED=false` 并重启 API，保留状态以供核对。界面显示服务未启用，基础收听不受影响。供应商认证错误会使当前进程关闭识曲，限流进入冷却；修正凭据或预算后按上述步骤重新核对，不能通过反复重启试探收费接口。
