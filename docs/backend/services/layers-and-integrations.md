# 服务分层与外部接入

## 代码分层

| 层 | 职责 |
| --- | --- |
| 路由 | 请求与响应适配、Schema、HTTP 状态 |
| 业务服务 | 业务规则、流程、事务边界 |
| 数据仓储 | Drizzle 查询与数据映射 |
| 外部适配器 | 对外请求、上游格式转换、调用边界 |
| 基础设施插件 | 配置、数据库、日志、错误处理 |

路由保持简洁；外部服务格式在适配器内转换，不向界面传播供应商特有字段。数据库行与公开 DTO 分别维护。

## 外部请求

为每类服务定义固定的基地址、超时、响应大小限制、有限重试和并发上限。校验返回数据，标识缺失或不可靠字段，不将上游数据默认为完整准确。

需要处理服务端 URL 访问时校验协议、域名和重定向目标，并阻止访问本机、私网及云元数据地址，避免将后端变成任意请求代理。

API 密钥通过服务器配置注入，日志和对外响应均过滤凭据。供应商、限额和授权条件在实际接入时补充，不因文档列出适配层而视为已开通服务。

手动识曲的采样、供应商上传、预算预扣与客户端状态分别封装；主播放仍直连音源，不改为后台持续代理。默认不配置或启用外部识曲，实际接口和限制见[识曲 API](../api/recognition.md)，持久运维状态见[额度决策](../../architecture/decisions/0004-recognition-allowance.md)。

## 配置与运行

启动时用 Zod 校验配置，失败时明确报告缺失项并终止启动。API 与后台任务共享配置定义，但各入口只要求自身必须的变量。

生产运行编译后的 JavaScript。停止时不再接收新工作，等待有界时间内的请求或任务结束，然后释放数据库和资源。
