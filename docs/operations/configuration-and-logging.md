# 配置与日志

## 配置归属

| 配置类型 | 生效时间与位置 |
| --- | --- |
| 前端公开配置 | 构建时写入静态资源，变更后重建 |
| 服务端运行配置 | 启动时读取并校验，变更后重启对应进程 |
| Compose 和 Caddy 配置 | 部署时加载，按组件要求重建或重载 |
| 运行私密配置 | 由 Jenkins 凭据或目标服务器注入 |

项目后续提供 `.env.example` 描述变量名、格式和示例值。真实环境变量文件不随构建分发，服务器密钥不使用前端公开变量前缀。

MySQL 连接、连接池上限、TLS、日志级别、代理信任范围、外部调用限制和任务时区统一进入配置定义，避免分散在代码中。

### MySQL 配置契约

以下为工程初始化时计划采用的变量名，只记录用途，当前尚无配置加载器或环境文件。

| 变量名 | 用途 |
| --- | --- |
| `DB_HOST`、`DB_PORT` | 数据库服务连接位置 |
| `DB_NAME` | 目标数据库，启动与迁移前核对 |
| `DB_USER`、`DB_PASSWORD` | 当前进程所需的运行或迁移身份，由受控环境注入 |
| `DB_CONNECTION_LIMIT` | 当前 API 或任务进程的连接池上限 |
| `DB_CONNECT_TIMEOUT_MS` | 建连超时 |
| `DB_SSL_ENABLED`、`DB_SSL_CA_PATH` | TLS 开关及受控证书路径，跨主机连接校验证书 |

API、任务和迁移入口分别注入自身的配置与权限。实际加载方式在初始化后记录并验证，不能认为仅创建环境文件就已生效。模板只提供变量名、说明和空值，真实值不打印或进入前端构建。

## 日志

API 与任务使用 Pino 输出 JSON。日志至少具备时间、级别、服务、运行版本和关联标识；请求使用 requestId，任务使用 runId。

过滤授权头、Cookie、密钥、带访问凭据的 URL 和敏感请求内容。错误日志保留可定位原因，但不无差别打印配置对象或完整上游响应。

## 保存与轮转

Docker 配置日志轮转和磁盘上限，避免日志占满数据库磁盘。Jenkins 构建日志与应用运行日志分别管理，发布记录关联两者的版本信息。

具体日志保留时长和容量在生产配置时确定。诊断材料在共享前脱敏，不将数据库备份或环境文件当作普通构建产物上传。
