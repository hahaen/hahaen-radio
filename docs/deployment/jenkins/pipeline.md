# Jenkins 流水线

状态：已确定流程，`Jenkinsfile`、任务和部署脚本待创建。

## 触发与参数

采用 Jenkins Pipeline，手动触发。输入目标环境、代码版本和发布范围；发布范围分为完整发布、前端更新和后端更新。

流水线解析并记录确定的 Git 提交，以该提交贯穿构建、产物和部署。对同一目标数据库加跨发布任务共享的发布锁，迁移与服务更新按阶段串行执行。

## 阶段

| 阶段 | 执行内容 | 失败处理 |
| --- | --- | --- |
| 获取源码 | 检出指定版本，记录提交 | 停止 |
| 安装依赖 | 固定 Node.js、pnpm，冻结锁文件安装 | 停止 |
| 工程检查 | 格式、Lint、类型、必要测试 | 停止，不部署 |
| 构建产物 | 构建共享包、前端和后端 | 停止 |
| 构建镜像 | Web、服务端与同提交迁移镜像；在隔离 MySQL 8.0.46 验证 | 停止 |
| 分发镜像 | 发布到已配置镜像仓库，验证目标可拉取 | 停止，保持旧服务 |
| 发布预检 | 核对当前版本、目标 MySQL、备份空间、连接权限与迁移清单 | 停止 |
| 数据处理 | 需要迁移时停止写入、校验备份，由 Drizzle Kit 单次执行已审核 SQL | 失败后停止，核对实际结构与迁移记录 |
| 更新服务 | Compose 更新指定镜像，保留数据卷 | 根据状态判断回退 |
| 验收 | API、数据库、页面、静态资源与日志 | 标记失败并执行适用的恢复流程 |
| 结果归档 | 记录环境、版本、镜像、SQL 状态和检查结果 | 保留诊断材料 |

完整发布执行所有适用阶段。仅更新前端且无数据库变更时不执行数据库迁移；单独更新服务仍需确认接口兼容。Drizzle Kit 版本由锁文件固定，发布不生成新 SQL，不执行生产 `push`，也不调用第二套迁移执行器。迁移入口不能依赖已经裁剪开发依赖的 API 镜像。

## 构建与部署节点

构建在专用 Jenkins Agent 的 Linux 容器环境执行。通过已有受控凭据连接目标服务器，部署机运行 Docker Compose。

采用镜像仓库分发不可变镜像，实际仓库地址与凭据由环境配置。构建目标架构与生产架构匹配。发布机不重新安装浮动依赖。

通过 `sh` 调用 Docker CLI 即可组织流水线；只有使用 Jenkins 的 Docker Agent 或对应 DSL 时才需要 Docker Pipeline 插件。具体插件和权限在配置阶段检查。

## 发布产物

记录本次提交、构建号、镜像标签或摘要、前后端版本组合、迁移清单、数据库备份标识和验收结果。归档不包含真实凭据、生产数据库或敏感环境文件。

应用回退和数据恢复见[发布与回退](../releases/release-and-rollback.md)。准备条件见[环境与凭据](environment-and-credentials.md)。
