# SQLite 与 Drizzle

## 连接与持久化

使用 SQLite、better-sqlite3 和 Drizzle ORM。数据库路径通过配置提供，落在服务器本机持久磁盘，由运行用户拥有读写权限。

连接启用外键约束、WAL 模式和合理的 busy timeout。初始化时确认 WAL 生效，权限允许创建及管理数据库相关文件。

## 并发边界

WAL 支持读取与写入更好地并行，但同一时间仍只有一个写入者。API 与任务共用数据库时，写事务保持短小，批量工作分批提交。

better-sqlite3 使用同步调用，长查询和大事务会阻塞所属 Node.js 进程。通过索引、查询限制和独立任务进程控制耗时，不能将默认同步调用视为无成本。

## Schema 与查询

Schema 放在服务端数据库模块，迁移 SQL 放在仓库 `migrations/`。按实际查询建立索引，使用外键、唯一约束和检查约束维护一致性。

时间统一保存为明确格式的 UTC 数据；字段格式在建表时确定。代码使用参数化查询，公开 DTO 经过独立映射。

Drizzle 提供类型化查询，不免除 SQL 审核、执行计划检查和数据迁移验证。初始表结构待业务模型确定后创建。

## 扩展条件

单机实例和本机磁盘是本方案前提。需要多主机写入、持续高并发写入或频繁出现写锁等待时，先测量瓶颈，再评估 PostgreSQL 和数据迁移。
