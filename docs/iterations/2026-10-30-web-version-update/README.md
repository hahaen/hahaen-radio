# 前端版本检测与强制更新

日期：2026-10-30。

## 需求与实际变更

前端发布后让已打开页面发现新版本，并以不可关闭的弹窗要求刷新。构建生成 `version.json` 与嵌入代码的同一标识；页面启动、每分钟及前台恢复检查，网络异常不误报。新版本弹窗使用夜航样式、中英文文案与原生模态焦点保护；唯一更新按钮在确认版本可获取后以临时查询参数刷新，保留收藏、偏好、登录及当前 URL 上下文；失败可重试。

行为与部署边界见[浏览器平台说明](../../frontend/platform/browser-and-storage.md#前端版本检测与强制更新)。仅需发布 `frontend`；`radio-api`、`radio-jobs`、Android 与数据库无需更新，不涉及新配置。

## Review 与验证

- 已对本次源代码、构建配置、测试和文档执行 Review；请求并发与卸载清理、缓存绕过、原生模态、子路径及首次接入边界均已复核。
- 使用 Node.js 24.22.1、pnpm 12.5.1；前端类型检查、改动文件 ESLint / Prettier、文档链接检查通过。
- 前端 Vitest：34 个文件、227 项通过，包含 11 项版本检查与异常恢复测试。
- `/radio/` 生产构建通过，六项资源预算全部通过；入口 gzip 约 214.5 KiB，低于 220 KiB 限制。更新模块及其共享依赖拆为启动即加载的静态分块，避免发现更新后才加载已被发布清理的旧分块。
- 生产构建 Playwright：20 项全部通过。浏览器项目为 Chromium、Firefox、WebKit 和 Pixel 7 模拟的 mobile-chromium；每项目覆盖 1440×900、390×844、320×700、844×390 视口，以及英文恢复补查。
- 浏览器验证范围：版本一致不弹窗、每分钟检测变化、恢复补查、503 不误报、唯一更新按钮与焦点、Escape / 遮罩不可关闭、断网重试、URL 与本地数据保留、无横向溢出和 axe 可访问性扫描。发布切换与电台目录为可控模拟；没有调用真实音源。
- 已人工查看桌面和手机截图，核对墨绿浮层、珊瑚色按钮、文字层级和可见焦点。

## 未完成与限制

首次上线前已打开的页面须主动刷新一次才能获得检测能力。浏览器挂起时不保证准时检测；恢复时补查。刷新后音频可能需要用户重新播放。移动视口自动化不能代替 iOS / Android 真机的后台调度与音频验收；本轮不追加真机音频专项。
