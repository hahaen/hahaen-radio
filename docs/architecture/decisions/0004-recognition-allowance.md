# 0004：识曲采用显式预算与持久化预扣

日期：2026-10-17。范围：默认关闭的手动识曲。

识曲可能产生外部费用，进程内计数不能约束重启后的总调用。采用人工授权的固定次数、预算标识与令牌指纹，存入独立私有额度文件；只允许既定单 API 实例独占访问。该文件属于运维状态，不改变 MySQL 业务数据及 Drizzle 迁移规则。

每次上传前串行预扣，通过文件同步、原子替换与目录同步完成持久化；不确定的上游结果不退款。缺失或损坏状态、错误身份、权限异常、并发实例或写入失败均关闭识曲。状态文件只保存计数、预算 ID 和令牌摘要，不保存令牌、访客信息、歌曲或音频。

使用数据库表管理额度同样可行，但当前只有一个 API 实例，私有文件可提供独立、可显式核对的授权边界。本决策不支持自动扩容或多文件共享一份预算；需要多实例时必须先改为共享原子账本并重新验收，不能只放宽锁限制。

不自动补充、覆盖或周期性重置额度。发布保留持久状态，恢复旧备份前核对供应商实际消耗。初始化与恢复步骤见[额度运维](../../operations/recognition-quota.md)。
