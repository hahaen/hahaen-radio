# 收听设置与系统播放控制

## 需求与实际变更

在个人清单基础上完成设置、睡眠、快捷键和系统媒体；同时实现 Enter/Esc 对应的实际沉浸视图与默认关闭的 30 秒闲置模式。元数据、歌词及音频增强仍在后续阶段。

- 上一站从成功收听记录初始化，仅保存和解析 ID，保持分享优先、暂停恢复与请求失效保护；清空历史同步清空导航。
- 设置提供中英界面、共享收听语言、实际音量与静音、操作提示和闲置开关；音量与静音只回写实际变化，避免跨标签页反馈。
- 睡眠支持关闭和 15/30/60 分钟，用独立 ID、截止时间与明确到期记录区分到期、取消与重设；恢复焦点、页面与可见性后复核，每个播放器到期只暂停一次。
- 全局快捷键覆盖播放、换台、视图、搜索、收藏、固定、静音及沉浸；输入、组合输入、修饰键、重复按键、原生按钮和模态面板保持自身操作。
- Media Session 逐项注册真实电台与播放控制，不生成直播进度或虚假曲名；缺少能力时保留基础播放。
- 夜航沉浸视图展示真实电台、位置与状态，共用既有播放器。唱片只在实际 playing 时转动，减少动态效果时静止；离开恢复入口焦点，按 `/` 离开时转到搜索。
- 设置继续使用原生模态面板；播放器实际高度继续为正文占位，手机保留 44px 操作目标。新增中文文案同步更新本地字体子集。

界面构图与不变量见[收听设置](../../frontend/application/listening-controls.md)。

## Review 与验证

本次范围为 Web 设置、平台适配、上一站导航、相关本地记录、共享语言选择和必要文档。检查了新旧状态互相影响、跨标签页、快速切换、可选能力、定时与监听清理、双语、焦点和手机布局。

浏览器验证发现原界面隐藏后再记录焦点会丢失入口；已在进入前记录，并在恢复可见后还原，随后复审并回归。人工复看也发现矮横屏纵向唱片会使标题经过固定播放器下方，已增加并排构图与标题边界断言；设置中的保存限制提示同时明确采用语义色。

`pnpm check` 的格式、Lint、TypeScript strict、100 项普通测试与前后端生产构建通过。完整 `pnpm test:e2e` 为 137 项通过、3 项桌面触摸合成不适用；英文 200% 设置追加 4 项通过。六项隔离 MySQL 用例本次不适用，未执行；数据库与接口均未改动。同步后复审与完整检查再次通过，收听控制回归 44 项通过；横屏修正后的 Web 构建、Lint 及受影响布局/200% 检查 24 项通过。Vite 仍提示部分分块超过 500kB，完整性能预算留待阶段 8。浏览器音源使用项目生成的可控 MP3，目录为明确测试样例；系统媒体动作在浏览器原生能力上观察注册与调用，不代替真实锁屏测试。睡眠通过受控时钟和实际媒体暂停验证，没有等待真实 60 分钟。

## 部署与未完成项

影响发布目标仅 Web 静态资源；API、任务、数据库结构和权限无变化，不需要 SQL、新环境变量或迁移顺序。本次没有执行 SQL、生产写入、镜像上传或部署。

真实 Android/iOS 的声音输出、后台挂起、锁屏与系统中断继续待设备验收；浏览器自动化不代替真实手机。本机按用户要求不执行 Docker 验证，镜像、Compose 与手动 Jenkins 材料在部署阶段实现，并由实际部署环境验收。

阶段 6 仍需当前曲目、歌曲收藏操作、外部搜索、歌词和可靠校时、音量统一与默认关闭的调台音效；识曲、产品说明、完整性能和可部署交付也未完成。完整目标保持进行中。
