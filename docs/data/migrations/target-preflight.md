# 目标迁移预检

已实现只读状态入口和迁移前后核对，用于目标发布在执行 SQL 前识别空库、待升级前缀、版本不匹配及部分建表状态。实际 MySQL 8.0.46 的隔离验收见[本轮记录](../../iterations/2026-10-17-migration-preflight/README.md)；完整目标发布执行器仍需继续接入维护、备份与回退。

## 入口

```sh
pnpm db:migrate status
pnpm db:migrate
```

两个入口显式加载 `.env.migration.local`，使用迁移身份；文件须先被 Git 排除、未跟踪且权限 600。status 不要求停写确认，不创建库、表或迁移记录。它会占用项目维护锁，与正在运行的备份或迁移互斥；锁忙返回失败，不把失败当作“没有待执行迁移”。

迁移镜像已包含 Schema、SQL、快照、Drizzle Kit 与编译入口，可执行 `docker compose run --rm migration status`。不要用已裁剪开发依赖且缺少迁移材料的 API 生产镜像运行该流程。本机 Docker 实测按用户要求留至部署环境。

## 检查内容

1. 读取当前提交的 Drizzle journal、SQL 与 MySQL version 5 格式快照；校验连续 idx、唯一文件名、严格递增时间及合法摘要。
2. 实际检查 MySQL 8.0.46、连接字符集/排序规则、UTC 与既定 TLS 条件，并验证完整元数据可见性。
3. 拒绝视图、非 InnoDB 基表、存储例程、触发器和事件；这些对象当前不在项目备份/迁移基线内，不能静默忽略。
4. 迁移历史必须逐行等于当前提交已发布序列的前缀，包括 SQL SHA256 和 created_at；拒绝额外、跳项、改过的文件或时间戳。
5. 实际表集合须等于最后已应用版本快照加 Drizzle 历史表，最新快照还须对应当前 TypeScript Schema 的表名。出现新表但迁移记录未完成，不能直接进入下一次迁移。
6. Kit 成功退出后再次核对源材料、完整历史和表集合；未完成或源材料在期间变化时仍按失败处理。

status 输出固定 migration_status 事件，以及 empty、tables、expected、applied、pending。列表包含迁移文件名、摘要、时间戳和预期表名，不输出 SQL、账号、连接位置、私有 CA 或配置值。迁移完成事件中的 applied 为本次迁移文件数量，total 为总文件数；已是当前版本时 applied=0，入口仅校验而不再次调用 Kit。

## 权限与首次初始化

迁移身份应拥有所选项目库必要 DDL/DML，并具备完整元数据可见性。当前检查复用已验证的备份可见性规则：源库直接 SELECT、SHOW VIEW、TRIGGER、EVENT，及全局 SHOW_ROUTINE（或已经具备的全局 SELECT/ALL）。仅使用角色、逐表权限或不完整可见性的身份不会被当作“库为空”。不自动创建账号、授予权限或提升 API/jobs 身份；实际生产权限由操作者配置并验收。

迁移前仍必须停止所有写入方、完成适用备份与副本校验，再设置 `MIGRATION_WRITES_STOPPED=true`。该变量不是服务停止机制，也不能代替进程、连接及其他写入方检查。

首次初始化需要操作者预先创建约定的空库并核对环境。只有状态证明没有表、视图、例程、触发器、事件时，才可在私有迁移配置设置 `MIGRATION_INITIALIZE_EMPTY=true` 后执行初始化；默认不允许直接初始化。入口不执行 CREATE DATABASE、DROP 或清空旧库，真正 DDL 始终由同提交 Drizzle Kit 执行。

非空库没有历史表、历史表空记录或物理表集合不匹配时，不能用初始化开关绕过。对已管理且确有待升级前缀的库，该开关不改变执行顺序或历史；它不是强制修复或重新建库选项。

## 检查的边界

本入口核对历史与表集合，不是完整数据库漂移检测器。列、索引、约束、排序规则例外、数据内容和迁移中的非建表变更仍须按既定 Review、独立升级/约束验收和实际应用检查完成；不能以一次 status 成功声称所有结构和数据正确。

它不证明停写、备份、独立存储或完整发布互斥已经完成。迁移工具不自动重试、修补历史或生成 SQL；MySQL DDL 可能隐式提交，失败后保持维护状态并先检查实际结构与历史，再决定修复或恢复。正式库执行不在当前目标授权范围内。

隔离测试会故意修改并恢复本轮临时库的历史字段、添加未管理表和模拟半完成建表，用于验证拒绝行为。这些是测试负例，不是生产修复步骤；不得复制为正式操作方法。
