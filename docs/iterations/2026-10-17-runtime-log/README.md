# 普通日志七天保留

## 需求与实际变更

补齐普通进程日志的时间、体积和敏感字段边界。API的Pino与任务固定事件接入同一原生目的地；生产Compose使用独立api_logs/jobs_logs卷，当前用户700目录、600文件，Docker日志为none。每小时/10MiB分段，默认七天过期，启动和运行中每分钟清理，同时限制每服务30MiB和200个文件，新片段提前预留容量。

固定投影只保存服务、版本、事件、服务端requestId、路由模板、状态和数字计数，剔除任意文本、完整地址、异常、请求与配置。未知或超大输入仅保留固定事件；I/O失败触发一次关闭请求，不回退输出原文。同步小写入处理部分写入，不逐条扫描目录，不作为业务持久状态或承诺断电不丢日志。

镜像声明文件日志能力并写入应用版本。镜像隔离检查改用独立限额tmpfs并读取真实文件；目标执行器在prepare时拒绝不支持该能力的候选，在建立维护attempt和停写前失败。任务启动验收改用共享探针，核对服务、实际服务端提交和事件时间不早于该容器StartedAt，避免把持久卷中的旧事件作为本次启动成功。

本轮没有Schema、SQL、API契约、页面或依赖变化。后端镜像、Compose、发布执行器与日志读取方式需作为同一版本交付；不自行执行Docker或实际发布。配置、停机清理延迟、慢磁盘、旧镜像回退边界与操作步骤见[运维说明](../../operations/runtime-logs.md)。

## Review 与验证

Review仅覆盖本轮日志目的地、API/任务接入、镜像/Compose、共享探针与相关发布代码及文档。检查字段来源、权限、过期及容量边界、文件资源、单实例约束、失败关闭、当前启动识别和发布顺序。复审发现目标任务探针仍依赖Docker输出，已一并修改；旧镜像能力检查位于prepare，不在维护开始后才暴露。普通日志不混入数据库备份和Jenkins归档。

新增10项普通测试：八项真实文件/Fastify用例覆盖低流量到期、重启清理、小时/体积分段、容量/数量、目录与文件权限/符号链接拒绝、实际请求字段剔除和故障关闭；两项原生探针/镜像边界用例覆盖旧启动、错版本、公开文件拒绝及旧镜像拒绝。时间测试使用可控时钟，体积用例实际写满超过10MiB；镜像编排仍是明确标记的模拟Docker。

编译后的真实API入口以本机临时私有目录启动，实际HTTP请求通过，日志探针确认版本及事件，查询参数没有落盘，SIGTERM后正常退出；临时目录与进程已清理。该检查未连接数据库，不代表生产数据库、Linux容器或任务自然调度验收。

完整检查与同步后复验均通过格式、Lint、类型检查、219项普通测试及前后端构建；10项MySQL用例在普通命令中跳过。同步没有远端变动，25个任务文件字节及权限完整恢复，复审后重复完整检查和编译API运行验证；99份Markdown与601条本地链接通过。详见[结构化记录](results.json)。数据库用例在普通命令中按既有设计跳过，本轮不伪造数据库运行结果；Docker实测按用户要求延期。本轮没有写入开发/正式库、创建远端任务、上传镜像或上线。
