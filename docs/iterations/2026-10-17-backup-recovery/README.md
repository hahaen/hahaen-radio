# 备份与隔离恢复工具

## 需求与实现

补齐逻辑备份、完整性验证、复制后隔离恢复、保留清理与受控 CLI。实现使用既定 MySQL 8.0.46 客户端、严格目标与身份边界、私有临时 option file、流式压缩、文件权限、互斥、大小和时间上限；不将账号、SQL、备份或连接值加入普通产物。

## Review 与验证

范围为本轮维护模块、入口、脚本、环境模板、测试和相关文档。Review 核对数据完整性、元数据权限、目标防覆盖、旧备份保留、子进程退出、错误输出、凭据清理和 SQL 实际范围。修正了客户端版本选项兼容、option-file 转义检查、子进程异常后等待 close、可见性不足的漏备份风险及测试现场清理边界。

首轮真实隔离验收通过：原生 8.0.46 mysqldump/mysql 生成备份，从另一个私有目录副本恢复（原备份已删除），核对 11 张表、3 条迁移、Unicode/引号/反斜杠/换行、约束和已使用额度，并启动编译 API 验证 readiness 与目录。实际使用已有、核对主机校验选项且仅绑定 loopback 的 SSH 通道，没有关闭外部 TLS 校验或安装数据库服务。

完整工程检查通过：格式、Lint、TypeScript、172 项普通测试与前后端生产构建；普通命令中的 10 项 MySQL 用例按设计跳过，本轮另执行专用真实恢复验收。8 项新增普通用例覆盖 option-file 转义、gzip/校验损坏、权限与链接、互斥、保留、目标保护、元数据权限、缺失客户端及取消清理。

补充权限、取消与异常边界后，真实恢复入口再次通过：源库中的不支持对象被拒绝；清理后查询 information_schema 确认两个本轮库已删除，API 已退出，无临时凭据与互斥文件残留。结果和精确源码 SHA256 见[结构化证据](results.json)。副本验证只涉及另一私有目录，不代表已具备异盘、远端备份或灾难恢复能力。

同步 upstream 无新增提交，17 个任务文件的内容、权限及空暂存区完整恢复。同步后仅复审本轮差异，再次通过完整工程检查（172 项普通测试、10 项数据库用例在普通命令中跳过）及专用真实备份恢复入口；实际查询确认本轮两个数据库已删除，编译 API 已退出。文档与源码证据对应关系已复核。

追加使用官方 8.0.46 my_print_defaults 对 4 组合成值进行实际 option-file 解析核对，覆盖引号、反斜杠、换行/回车/制表符、空格、中文与注释字符，逐字节一致；未连接账号或使用真实凭据。

## SQL 与交付边界

没有新增迁移，实际写入仅限本轮专用测试库；开发库和正式库未变。本机没有 Docker，实际 Linux 运维节点、容器、真实备份身份/TLS、每日调度及独立物理存储仍需部署前验收。Jenkins、每日调度、独立物理副本、正式恢复运行手册和日志保留继续推进，不将隔离恢复成功等同为正式恢复已演练；本轮不代表完整目标完成。
