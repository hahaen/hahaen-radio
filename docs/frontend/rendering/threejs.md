# Three.js 渲染约定

## 当前实现

`apps/web/src/graphics/globe.ts` 封装原生 Three.js 和 OrbitControls，`GlobePanel.tsx` 负责懒加载、状态与恢复。地形取本地资源，电台取完整精简目录，详见[探索目录](exploration-data.md)。

地球、轮廓与标记使用批量 Geometry；只在相机、尺寸或数据变化时申请帧，隐藏或切换到流派时停止帧循环。像素比上限为窄画布 1.5、宽画布 1.75；这属于控制参数，不等于已完成真实手机帧率验收。

方向键、鼠标和触摸操作由引擎处理；候选稳定约 650ms 后选择，界面重新核对选择版本、暂停与固定状态。程序定位沿球面插值，减少动态效果时直接定位。销毁清理计时、观察器、监听、几何、材质、控件和上下文；上下文恢复只重建图形，不重建音频。

## 技术与模块边界

使用 Three.js 原生 API、WebGL 2 和 GLSL。场景模块负责初始化、尺寸变化、数据更新、交互、帧循环和销毁。React 组件通过场景控制接口传递变化。

Three.js、附加模块及对应类型声明的版本需要匹配。渲染初始化失败时保留 DOM 界面和基本操作能力，实际降级表现随界面设计明确。

## 渲染与性能

- 大量点状对象优先使用 `Points` 和 `BufferGeometry`，重复几何使用实例化。
- 标签和复杂对象按距离、密度和可见性控制数量。
- 统一帧循环管理相机、动画和渲染，避免每个对象独立启动循环。
- 根据屏幕和设备能力限制像素比、粒子数量与后处理成本。
- 坐标转换、索引生成等适合的重计算可放入 Web Worker。
- 页面不可见或场景不活跃时减少不必要计算，返回后正确恢复。

具体帧率和设备预算待真实场景与目标设备确定后测量，不预先将目标写成已达到的性能结果。

## 坐标与交互

集中封装地理坐标、场景坐标和屏幕坐标转换。输入统一处理鼠标、触摸和缩放；拾取策略根据点密度选择射线或屏幕距离方法。

相机和渲染参数集中配置，界面层不直接修改内部对象。高频输入保持在场景内部，只在选择等语义状态变化时向外发事件。

## 资源生命周期

销毁时停止帧循环，移除监听器，释放 Geometry、Material、Texture、RenderTarget 和后处理资源。共享资源由明确的所有者释放，防止重复释放。

处理容器尺寸变化、WebGL 上下文丢失和重建。开发环境下 React 生命周期重复执行也应保持初始化与清理配对。
