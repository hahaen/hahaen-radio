# Jenkins 流水线

根 [Jenkinsfile](../../../Jenkinsfile) 用于文件夹 `radio` 中的三个手动任务。每个任务只有 `BRANCH` 分支选择，关闭快速 Filter，不在构建历史增加分支/提交描述。代码推送不触发发布，也不另设完整发布入口。

| 任务 | 发布内容 |
| --- | --- |
| `radio-frontend` | 前端静态产物，由共享 Nginx 服务 `/radio/` |
| `radio-api` | 仅 `radio-api` 容器 |
| `radio-jobs` | 仅 `radio-jobs` 容器 |

## 执行流程

1. 人工发起者须同时列于分发和部署用户清单。校验所选分支，核对抓取引用与 HEAD，固定完整提交；后续不再追随分支移动。
2. 从节点持久 pnpm store 冻结安装，优先复用缓存；执行对应应用及共享契约的类型检查、单元回归。格式、lint、发布工具回归与完整浏览器专项在开发验证阶段按改动执行，不在每次手动发布重复。
3. 目标节点以只读方式核对实际迁移历史、已安装组件与兼容声明。前端使用当前正式结构对应的迁移工具检查，不触发新结构变更。
4. 复用第一阶段的源码和依赖，不再重复检出/安装；仅在服务器本机 Docker 构建所选部分，后端存在待迁移项才构建迁移镜像。检查原生架构、revision、镜像 ID 和模块/静态文件后，固定 `sha256:<image-id>`，不上传或拉取项目镜像。
5. 交接材料绑定组件、完整提交、平台、Docker 引擎 ID、目标站点、数据库指纹、迁移清单和内容摘要。目标节点须使用同一引擎，在新工作区检出确切提交，验证交接和私有环境文件。
6. 无迁移自动继续；有迁移或首次空库初始化才一次确认数据库变更。实际执行器持有本机文件锁及数据库发布锁，再次核对结构，执行维护、必要停写/备份、单次迁移、所选部分更新和健康检查。

两个专用节点各一个执行器，使用服务器上的同一个 Docker 引擎；构建与目标仍使用不同系统身份。每任务禁并发和阶段重启，总上限 45 分钟；跨任务共享目标锁防止并发更新。没有给 SQL 或状态性阶段添加自动重试。旧工作区和失败现场由管理员核对后清理。

构建、预检、发布工作区在本次使用完毕后清理，保留的依赖 store 位于各身份的工作区之外。只读预检通过、确认没有未处理 attempt 后，才清理同一串行任务编号更小的旧 plan/release 工作区；保留当前及未来构建、其他任务、不同所有者目录和符号链接。清理失败只输出固定提示，不掩盖发布结果。Dockerfile 先复制依赖清单，使用持久 BuildKit pnpm cache，再复制应用源码；仅改业务代码时复用依赖层。Node、Caddy 基础镜像固定版本及摘要，不再每轮 `--pull`；每月及安全修复时通过依赖升级流程审核更新摘要，不自动改变基础镜像。既存历史工作区不由本次脚本修改立即删除，清理随下一次相应手动任务执行。

## 版本、配置与产物

`component-source.json`、`component-build.json`、`component-check.json`、`component-release.json`、`component-handoff.json` 和 `source.json` 只记录必要版本与验证元数据，按明确文件名归档。禁止扩大成整个私有目录。不再使用镜像仓库认证凭据或临时 `DOCKER_CONFIG`。

目标配置显式加载 `/home/hahaen/radio-prod.env`。每个组件的实际 revision、不可变 image、validationRun 分别存入 `state.json` 的 `components`，不存在共用的 serverRevision。API 和任务即使来自同一源码，也保持独立记录和更新。

Jenkins 新产物附带 `buildNumber`，本地标签为 `radio-local/<component>:<SHA>-<构建编号>-<随机标识>`，OCI version 标签记录 SHA 与构建编号；原有无 buildNumber 的记录仍可读取。`previous` 只在发布尚未成功时临时保护旧版本，成功后清空本组件条目，`previousVersions` 仅保留上一版提交及构建编号，不引用旧产物。

兼容策略位于 `deploy/compatibility/policy.json`：默认要求契约及结构摘要相同。确需混合版本时，须审核真实兼容窗口并声明允许的摘要；不能通过修改状态伪造兼容。有结构变更时停止两个写入服务，未选中的服务使用其原镜像和私有配置快照恢复。

当前兼容清单允许旧契约摘要 `a371c03455a214cc8addabd4b806a007ba37db0d2706ab96efb2e34484e8b552`：新增国家搜索和语言归一化辅助代码及导出，既有 DTO、接口字段和迁移清单保持不变，新代码保留旧语言值的筛选支持。组件可逐个更新，无需为本次兼容声明执行迁移或修改服务器配置；为使新版目录语言处理在同步时生效，建议 API、后台任务、前端依次发布。未知契约及不兼容结构仍拒绝发布。未来修改契约时必须重新审核清单，不把这项许可视为所有后续版本的兼容保证。

账号功能的兼容窗口另允许线上旧契约摘要 `76709ac485937b849bdd5f40c4fddbb4711a2e431e4fd4b9f73a5fbedcc6816d`，以及前三条迁移组成的结构摘要 `a813e53de86d186b60dc13a5a71aecdfcd0557f7606379c48aa53ee23163e144`。账号接口独立新增，原有接口字段不变；`0003_accounts` 仅新增账号相关表及其内部约束，旧 API 与后台任务访问的表不变。因此，账号 SQL 已执行而组件仍是旧版本时，可以保留真实组件记录，先发布 `radio-api`，成功后再发布 `radio-frontend`；后台任务可保留原版本。不能先发布账号前端依赖尚未上线的新 API，也不需要重跑已完成的 SQL。上线前仍核对新表权限及 Nginx 请求体配置，详见[账号功能记录](../../iterations/2026-10-23-account-sync/README.md)。该声明不豁免实际迁移历史、未知契约或其他结构变更的检查。

只读预检的 `component_plan_failed` 会附带固定原因：`CONTRACT_INCOMPATIBLE` 表示需要审核并声明混合版本兼容性；其他错误为 `TARGET_PREFLIGHT_FAILED`。提示不输出原始异常、配置值或连接信息。

部署、回退和恢复详见[目标阶段](target-stage.md)、[发布与回退](../releases/release-and-rollback.md)。实际上线结果见[正式部署记录](../../iterations/2026-10-17-production-deployment/README.md)。

按用户选择，成功发布后只保留当前组件版本；本次淘汰的旧镜像、静态目录和配置快照才可清理，结构工具镜像另行保护。清理在页面/静态资源、就绪接口和目录接口检查通过后执行，不扫描其他任务的活动构建或其他项目，也不全局清理 Docker 缓存。无迁移失败会自动恢复本次发布前的版本；成功清理后再回退需从指定旧 SHA 重新构建，步骤见[发布与回退](../releases/release-and-rollback.md)。
