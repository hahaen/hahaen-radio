# 首次服务器部署准备清单

日期：2026-10-17。本轮根据现有代码和部署材料分析上线准备，不连接目标服务器、不创建正式库、不运行迁移、不分发镜像或触发发布。实际服务器资源和服务状态尚未核对。

## 当前交付状态

- 已有前端、Fastify API、独立任务进程，以及 Web、server、migration 三类镜像目标、Compose、Caddy 和手动 Jenkins 流程。
- 仓库记录开发库已应用三条迁移，正式库未创建、未迁移、未上线。本轮没有连接数据库重新核对该记录。
- Linux/Docker 镜像运行、持久卷权限、Jenkins 插件及生产 TLS 尚待实际环境验收；本地构建与功能证据不等于服务器部署通过。
- 生产 Compose 不包含 MySQL 服务，必须先准备可访问的独立数据库服务。迁移容器不会自动创建正式库。

## 需要先确定的信息

| 项目 | 部署方需要提供或核对 |
| --- | --- |
| 应用服务器 | 所在区域、系统版本、CPU 架构、内存、可用磁盘、现有端口占用和管理方式；项目基线为 Ubuntu 24.04 LTS，镜像平台为 linux/amd64 或 linux/arm64 |
| 公网入口 | 准备使用的域名、DNS 管理权、80/443 可达性；已有反向代理占用端口时先确定接入方案 |
| 数据库 | 既有 MySQL 服务能否供生产使用、实际版本、网络路由、数据库证书身份及可信 CA；目标基线为 MySQL 8.0.46 |
| 发布平台 | 是否已有 Jenkins、独立 Linux 构建节点和应用目标节点，以及项目镜像仓库 |
| 备份存储 | 主备份目录、异盘或远端文件系统副本、容量及实际恢复条件 |
| 网络出口 | 构建节点能访问依赖、浏览器和镜像源；应用节点能访问电台目录、曲目与歌词服务 |

不能仅凭功能数量给出已验证的最低服务器规格或并发容量。应用运行与 Jenkins 构建分别评估资源；构建还会运行三浏览器检查和临时 MySQL，不能把运行服务的预算直接当作构建预算。音频由浏览器直连外部电台，应用服务器通常不转发音频；用户侧网络仍影响实际播放。

## 准备顺序

1. **服务器与入口**：核对系统和原生架构，安装 Docker Engine、Buildx、Compose；当前使用 raw env_file，需要 Compose 2.30.0 或以上。正式域名解析到入口，确认 TCP 80/443，按现有配置使用 HTTP/3 时确认 UDP 443。API 3001 和数据库端口不向公网开放。部署到已有服务器时先检查现有 Web 服务，避免直接争抢端口。参考 [Docker Ubuntu 安装](https://docs.docker.com/engine/install/ubuntu/)、[Compose env_file 格式](https://docs.docker.com/reference/compose-file/services/#format)与 [Caddy 自动 HTTPS](https://caddyserver.com/docs/automatic-https)。
2. **正式数据库**：由管理员显式创建 `ha_radio`，指定 utf8mb4、utf8mb4_general_ci；业务表由已审核 Drizzle Kit 迁移管理。分别准备 API、jobs、migration、发布锁及备份所需身份和最小权限。生产配置强制 TLS，DB_HOST 必须匹配证书身份，CA 必须可信且在容器内可读。容器内 localhost 指向容器本身，不能直接沿用开发机数据库隧道地址；禁止关闭 TLS 绕过校验。详见[数据库约定](../../data/database/mysql-and-drizzle.md)。
3. **私有运行配置**：在 Jenkins 工作区外准备 target JSON、API/jobs/migration 各自环境文件、发布环境文件与 CA。凭据文件 600，私有目录 700；维护标记目录按执行器要求为 755，只保存无敏感内容的标记。容器环境文件使用 raw KEY=value，不能照搬带引号的 Node 环境文件。模板与约束见[目标执行器](target-executor.md)。识曲默认关闭，首次上线不需要供应商令牌。
4. **持久状态与备份**：准备证书、日志、识曲状态卷及发布状态目录；安装共享维护锁、独立备份身份、原生 MySQL 客户端、运维包与固定 helper。正式备份副本要求不同文件系统设备，并人工确认故障域；另一同盘目录不满足现有生产检查。备份与隔离恢复验证后再启用每日定时，见[每日备份](../../operations/daily-backups.md)。
5. **Jenkins 与镜像仓库**：创建手动 Pipeline from SCM 任务，配置专用 `haen-linux-build` 与独立 `haen-linux-target` 节点，不能将唯一构建 executor 同时作为目标节点。两节点使用项目固定的 Node.js 24.9.0、pnpm 12.5.1；构建节点还需要 Playwright 系统库。准备代码检出权限、镜像推送和独立只读拉取凭据，以及两类审批人、目标站点与数据库配置指纹。详见[环境与凭据](../jenkins/environment-and-credentials.md)及[人工目标阶段](../jenkins/target-stage.md)。

若只准备了一台新服务器，应用可以使用单机 Compose，但现有 Jenkins 流程的构建节点仍应独立准备。若需要改为单机手动发布或复用已有反向代理，应先明确变更后的发布方案，再调整和验证；不能把执行几条 Compose 命令视为已覆盖当前发布、备份与恢复流程。

## 首次发布与验收

1. 固定完整源码提交；先以 `PUBLISH_IMAGES=false`、`DEPLOY_TARGET=false` 验证 Jenkins 语法、工程检查、三类镜像构建、隔离 MySQL 迁移及容器启动。失败先修复，不使用正式库做构建测试。
2. 验收通过后，人工发起镜像分发；再经独立目标审批，以 `full` 范围首次部署同一批不可变镜像。
3. 核对正式库确实为空、所有写入方停止，再按实际状态确认空库初始化和首次目录同步。迁移入口应用当前三条已审核迁移，不在发布时临时生成 SQL，不手工改写迁移历史。
4. 完成首次真实电台目录同步后，再通过 API readiness、Web 同域代理和静态资源检查，恢复一个 jobs 进程并退出维护。仅启动容器而未同步目录时，不能视为应用就绪。
5. 如需附近城市与可证实的时区补全，按[离线地名导入](../../data/offline-geography.md)使用任务身份导入 GeoNames，再同步目录。当前空地点表允许目录同步，地点导入不是基础播放的硬前提，也不会由建表迁移自动完成。
6. 在最终 HTTPS 域名下检查电脑和手机：页面、搜索、播放暂停、切台、收藏与刷新恢复；同时核对数据库 TLS、任务启动、持久卷权限、备份副本和重启状态。外部电台连接受用户网络、来源服务及浏览器规则影响，不能只用 HTTP/IP 访问结果替代最终域名验收。
7. 保存实际提交、镜像摘要、迁移状态、配置用途、验证结果及遗留事项；不归档真实环境文件、凭据或展开后的 Compose 配置。失败依据持久状态保持维护并按[发布与回退](release-and-rollback.md)处理。

## 本机 SSH 直接推送配置

2026-10-17 用户选择直接推送代码，并确认添加账号级 SSH 公钥。已创建本机专用 Ed25519 密钥，私钥位于 `$HOME/.ssh/id_ed25519_gitee`，只保存在本机；`.ssh` 目录为 700，密钥文件及 SSH 配置为 600。账号级公钥可访问该账号有权限的仓库，实际操作仍受仓库角色与分支保护限制。

本机 `Host gitee.com` 显式选择专用密钥，启用 `IdentitiesOnly yes` 和 `StrictHostKeyChecking yes`。主机公钥与 [Gitee 官方指纹](https://help.gitee.com/account/gitees-ssh-key-fingerprints)核对后写入本机 known_hosts；没有关闭主机校验。原 SSH 配置已私有留存，既有其他主机配置保持原样。公钥内容、私钥、账号验证密码及截图均不写入可提交文档。

项目增加 `gitee` SSH remote，`origin` 与 `origin/main` upstream 保留。两个 remote 独立维护，不设置自动镜像或多地址隐式推送；在需要更新两边时，对同一提交分别执行普通推送，再核对两个远端的完整提交号：

```sh
git push origin main
git push gitee main
```

本轮已通过真实 SSH 账号认证、私有仓库读取和普通快进推送，将此前未同步的归档提交 `c256868` 推送到 Gitee，并核对完整提交号一致。随后提交本节文档并分别推送两个远端，交付以最终核对结果为准。本机文件权限、专用密钥选择和既有 SSH 配置保留检查通过；本轮只涉及本机连接配置和文档，不运行应用构建或数据库测试。

仓库 WebHooks 页面显示没有配置，镜像列表为空；本轮没有创建自动同步、Jenkins 任务、镜像发布或服务器部署。以后新增其他本地项目时，仍需为对应项目单独配置 remote；账号公钥可复用，不需要重复上传同一公钥。若撤销本机访问，应在 Gitee 账号删除对应公钥并核对实际失效，不删除其他设备公钥。
