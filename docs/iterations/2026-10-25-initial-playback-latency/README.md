# 首次起播等待优化

## 需求与实际变更

手机网页与 Android 首次点击播放出现较长等待。正式网页观测到约 8.6 秒后才发出媒体请求，前段连续获取 17 页中国电台列表；这是一次桌面浏览器网络观测，不代表所有手机环境的固定耗时或真实出声时间。

- 新增 `GET /api/v1/stations/random-china`：在服务端按真实 `CN`、可用、有线路、非宗教及排除 ID 选取随机候选，返回完整详情及播放线路。无候选返回 `station: null`；人工屏蔽仍参与查询。候选总数与随机偏移使用同一目录版本，每次最多两次目录查询、每次只读取一个详情，不逐页传输列表，服务端无新增缓存或数据库结构。
- 网页与 Android 改为一次随机请求，直接使用返回线路，避免补查详情。网页启动时提前预选并保持暂停；Android 同样静默预选，点击播放后才准备媒体。
- 正在预选时点击播放复用原请求；暂停、手动选台或离开时保留原有取消与旧响应失效规则。分享链接、恢复已有电台及后续随机切台行为保持原有范围。
- Android 版本为 `0.1.2` / versionCode `8`，沿用应用 ID 与既有签名；本轮构建结果见下文。

## Review 与验证

新增网页回归在改动前复现：预选期间点播放触发两次选择，且初始选择仍走分页接口。针对本轮服务端、网页、Android、测试与文档执行 Review，核对地区及可用性、空候选、排除与屏蔽、随机范围、预选复用、暂停、手动选择覆盖、资源清理与发布兼容顺序。Review 过程中修正 Android 已取得详情时同步结束协程导致已完成任务覆盖 `resolving` 的风险，使用先赋值再启动的延迟协程。

最终结果：已安全保存本次改动，拉取 `origin/main` 并 fetch `gitee/main`；两边均无新提交、无冲突。恢复后核对本次差异和空暂存区完整一致并删除本次备份，复审无未解决问题，以下适用检查已在同步后再次通过：

- 定向 Vitest：目录/API、网页音频与选台共 73 项通过；服务端与网页 TypeScript、定向 ESLint、Prettier、文档链接与差异检查通过。
- MySQL 8.0.46：新隔离库执行现有 Drizzle Kit 迁移与目录、账号、诊断用例，共 15 项通过，测试结束后删除隔离库。默认入口首轮先因隧道未启动受阻；恢复隧道后，旧同步用例的 5 秒上限导致超时及后续干扰，复验使用 30 秒单用例上限。新增用例按快照保留规则显式排除早前测试电台，修正了首次空候选断言的测试隔离。未改动运行时超时、数据库结构或开发/生产业务数据。
- 浏览器：`initial-station.spec.ts` 与 `welcome.spec.ts` 在 Chromium、Firefox、WebKit 与 Pixel 7 模拟项目共 44 项通过，覆盖静默预选、分享暂停、欢迎页与可控 MP3 解码；新增“预选期间点击播放”专项 4 项通过，确认点击不新增随机请求、不补查详情且媒体时间推进。新用例已排除 React 开发 StrictMode 在点击前取消并重建初始化请求的影响。视口为 1440×900、390×844、320×700、844×390；已查看 1440×900 与 390×844 的预选暂停截图，未见横向溢出或控件遮挡；手机模拟不代替真机听音。
- 构建：服务端与 Vite 生产构建、前端资源预算通过；保留已有大包体提示。Android JVM 52 项通过；Debug/Release Lint 均为零错误，分别有 52/53 项警告；Debug 与 Release APK 构建成功。
- Release APK：`android-packages/release/声屿HAEN.apk`；核对版本为 `0.1.2` / `8`、签名和 16KB 对齐通过，归集包与构建原包一致，私有签名文件保持 Git 排除及 700/600 权限。未安装至手机。
- 开发目录只读测量：直接调用新 API 三次均为 200、返回 `CN` 和线路；首次 2249ms 包含本地 Fastify 初始化，后两次为 411ms、403ms。该测量经过本机数据库隧道，未连接音源，不代表生产请求或手机实际出声耗时。

## 更新范围与未完成事项

需要先手动更新 `radio-api`，再更新 `radio-frontend`，Android 使用新安装包；旧网页和旧 App 仍可使用原接口。无需 SQL 或数据库迁移，无需 `radio-jobs` 或运行配置变更。本轮不触发 Jenkins、不发布或上传安装包。真实手机起播时间、真实电台听音和生产发布后的效果尚未验证；电台直连、网络与缓冲耗时不在本次优化可保证的范围内。
