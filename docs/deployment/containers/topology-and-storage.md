# 容器拓扑与持久存储

## 服务组织

| 服务 | 镜像与职责 | 数据访问 |
| --- | --- | --- |
| 共享 `nginx` | 现有 HTTPS 网关，直接提供 Radio 静态文件并代理 API | 只读挂载 Radio 的公开发布根与维护标记 |
| `api` | Node.js 24 Debian slim，运行 Fastify | mysql2 连接池访问 MySQL |
| `jobs` | 与 API 相同的服务端镜像，使用任务入口 | 独立连接池访问相同数据库 |
| 迁移入口 | 同一提交构建的工具镜像，包含固定版本 Drizzle Kit、mysql2、配置与迁移材料 | 使用迁移权限单次连接 MySQL |
| MySQL 服务 | MySQL 8.0.46；连接现有服务，或另行配置独立容器 | 自管模式由数据库进程独占持久数据卷 |

前端发布从已验收的 `web` 产物镜像提取文件，原子切换公开目录；正式环境不启动该镜像。后台独立部署需要协调 `api`、`jobs` 和数据库版本。具体镜像名称、注册表、端口和卷名称在目标环境确认后配置。

当前已实现[构建与运行配置](local-and-image-build.md)，实际首次上线状态见[正式部署记录](../../iterations/2026-10-17-production-deployment/README.md)；开发库和正式空库已创建。数据库作为独立服务管理，应用发布不自动升级 MySQL 引擎版本；新增自管数据库与连接既有数据库是两种环境方案，部署时明确选定。

## 路由和网络

仅共享 Nginx 向外暴露已有 HTTP/HTTPS 端口，Radio 不新增宿主机端口。API 通过 Compose 内部网络访问；数据库端口限制在应用需要的内网或容器网络范围，不默认映射到公网。跨主机连接使用经过验证的 TLS 与访问控制。

共享 Nginx 对 `/radio/api/*` 剥除 `/radio` 后代理，后端保留 `/api/v1` 前缀。前端路由回退只用于页面请求，不能将不存在的 API 或静态资源错误回退为 HTML 成功页。

前端 HTML 与资源采用重新校验策略。HTTPS 证书继续由现有网关管理，应用发布不改动其证书目录。

## 持久存储

| 内容 | 规则 |
| --- | --- |
| MySQL 数据 | 自管模式仅 MySQL 进程挂载持久卷；现有服务遵循其存储管理方式 |
| 备份 | 独立目录，并有独立存储位置副本 |
| 前端版本 | 项目 `web/releases/` 保存公开静态文件与内容摘要，`current` 原子指针选择当前版本；共享 Nginx 只读读取 |
| 运行配置 | 由环境文件或受控挂载注入 |
| API/任务普通日志 | 独立api_logs/jobs_logs卷；700目录、600文件，七天及容量限制见[说明](../../operations/runtime-logs.md) |

API、任务和迁移入口均不挂载 MySQL 数据卷。发布保留数据库及证书状态，禁止将清理数据库卷或重建目标库作为例行应用更新步骤。数据库备份不随前端构建、镜像打包或工作区清理覆盖。

## 构建

使用多阶段 Docker 构建，产生 Web、服务端和迁移工具镜像，目标架构与运行环境匹配。迁移工具目标保留固定版本的 Drizzle Kit、mysql2、配置、SQL 和元数据；生产 API 可裁剪开发依赖，不以它是否包含迁移 CLI 作为隐含前提。

数据库凭据只在运行时注入，不进入构建参数、镜像层或前端资源。镜像验收使用独立 MySQL 8.0.46 测试库验证连接和迁移，不连接生产库完成构建测试。

初始化构建配置时显式排除本地私有配置、敏感归档与工具目录，不仅依赖 Git 忽略规则；这些材料不进入 Docker 构建上下文或发布包。

镜像使用提交标识或发布标识形成不可变版本，运行配置记录具体版本。全新机器构建和目标服务器启动均属于上线前验证内容。
