# 大目录与连续切换验证

## 需求与范围

推进阶段 8，补齐不少于 3 万条目录的客户端规模检查和反复切台、视图切换后的资源趋势观测。本轮仅增加验收用例与文档，不修改产品行为，不调用真实识曲或写入数据库。方法、阈值与适用边界见[规模验收说明](../../engineering/scale-and-stability.md)。

## Review 与结果

Review 范围为本轮测试、导航及状态文档；检查每片数量、目录格式、原生媒体时钟、稳定的两台切换、采样和请求计数，避免将可控输入当作外部服务结果。已在运行前修正千位分隔显示匹配和首次选台后才能固定的前置条件。初次运行还发现测试入口需使用仓库根可解析的契约路径，搜索必须显式提交；已核对现有交互并修正测试，未改动产品逻辑。

全项目首轮有 3 项通过，WebKit 在请求总数断言失败。trace 证明 61 次播放各有一次 bytes=0-1 探测和一次音源 Range 请求，合计 122，属于有限正常请求而非增长故障；原阈值 120 漏计初始播放的两次请求，已修正为 61×2 并保持其他边界。修正后 Chromium、Firefox、WebKit 和移动 Chromium 共 4 项全部通过；未降低媒体时钟、DOM、堆或监听器检查。完整工程检查（格式、Lint、类型、164 项普通测试、生产构建）通过；10 项真实 MySQL 用例在普通命令中按设计跳过，本轮没有数据库改动，相关真实验收仍见诊断归档。测试阈值修正后重新通过该文件的格式、Lint、工具类型检查与全部 4 项规模用例。文档链接和差异检查通过。

四项均只读取 30 个目录分片，刷新后没有额外分片请求；首次目录完成时没有电台详情扇出，60 轮后详情为 61 次。每轮只有一个音频元素和画布，三次采样的实际媒体时间前进；暂停观察 1.2 秒没有新增音源请求。页面异常为 0。60 轮是短时回归，不能据此认定长期无泄漏、GPU 回收或手机帧率达标。

真实手机触摸、后台音频、系统中断和帧率仍需 Android Chrome / iOS Safari；浏览器模拟不能代替。此前真实目录和至少 10 个外部电台已有独立记录，本轮不将合成测试加计为真实台。

同步 upstream 无新增提交，安全保存并完整恢复 10 个任务文件后，仅复审本轮差异，无未解决问题。同步后再次通过完整工程检查和全部 4 项规模用例；文档与结构化结果的内容、链接及测试文件 SHA 对应关系已复核。
