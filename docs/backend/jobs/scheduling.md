# 后台任务调度

## 运行组织

API 与后台任务使用同一服务端工程和镜像，通过不同入口启动。基线运行一个任务进程，使用 node-cron 调度。

目录任务已实现为每日 UTC 02:00，`pnpm jobs` 启动独立调度进程，`pnpm catalog sync` 手动执行；启动时不会隐式同步。持久记录时间统一使用 UTC。

## 执行约定

- 任务可重复执行，按稳定标识去重或执行幂等更新。
- 同一任务避免重叠执行，不能仅依赖进程内布尔值。
- 通过 MySQL 原子条件更新或短事务取得任务租约，记录持有者、到期时间和续租状态。
- 长任务分批处理，每批短事务提交，支持从安全检查点恢复。
- 外部请求设置并发、超时、重试次数和整体运行时限。
- 任务失败保留错误摘要与进度，不无限立即重试。

当前租约有效期 2 分钟、30 秒续租，数据库时钟判断到期。每批 200 条暂存和最终发布事务都锁定租约并核对令牌；过期旧令牌不能发布，旧任务释放不能覆盖新令牌。取消在抓取和每批写入边界生效。目录校验和清理细则见[目录管线](../../data/catalog-pipeline.md)。

## 与发布的关系

数据库迁移前停止任务并等待当前写入结束。恢复后只启动一个任务进程，确认不会重复调度。

记录每次运行的标识、起止时间、状态、处理数量和错误摘要。跨重启的任务状态保存在数据库中，内存缓存不承担唯一执行记录。
