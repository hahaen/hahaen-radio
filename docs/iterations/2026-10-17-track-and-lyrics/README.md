# 曲目信息、歌曲收藏与歌词

## 实际实现

- 新增只读曲目和歌词共享契约、OpenAPI 与接口；只查询正在收听的电台线路，不开放 URL 代理。
- 有界 ICY 元数据短读、请求合并、缓存、并发与令牌上限；不兼容线路如实降级，直播歌曲时间保持未知。
- 固定 LRCLIB 适配器校验响应、匹配歌曲身份、保留版本和署名；支持纯文本、时间行和纯音乐，限制总量、请求速率并遵循上游冷却。
- 曲目面板与沉浸共用状态，换台和线路后旧结果失效；系统媒体只有身份一致时才展示歌曲。
- 歌曲收藏、取消、复制、外部搜索及既有文件迁移共用同一格式；复制不可用时显示可选择的文本。
- 时间戳默认静态。用户明确标记起点或某句后才进行手动跟随；支持偏移、暂停跟随、实际暂停时冻结、换歌和版本重置。

设计见[曲目与歌词交互](../../frontend/application/tracks-and-lyrics.md)，接口边界见[曲目 API](../../backend/api/tracks.md)。

## Review 与验证

本次 Review 仅覆盖新增曲目模块及相关界面、平台、存储、共享契约与文档。重点检查远程请求边界、取消与资源清理、有限缓存、输入校验、旧线路信息、词曲匹配、手动时间语义、跨标签页、双语与双端布局。

Review 已修正系统媒体在切台瞬间可能读取上一个曲目快照的问题，改为同时匹配电台及线路 ID；歌词计时与媒体播放进度保持明确区分。

格式、Lint、TypeScript strict、119 项普通测试及前后端生产构建通过。完整浏览器回归为 169 项通过、3 项桌面触摸合成不适用；元数据失败场景追加 4 项通过，当前 176 个项目用例中共 173 项已通过。曲目模块 32 项回归通过，五种视口补充检查 4 项通过。同步后重新 Review，通过完整检查及 76 项曲目/收听控制回归，文件恢复内容与权限已核对。六项隔离 MySQL 用例本次不适用，表结构和持久化数据访问规则未改变。Vite 仍报告部分分块超过 500kB，性能预算留待阶段 8。

额外 Review 修正了：读取失败后的旧曲目增加“上次观测”标识并清理系统歌曲信息；同一歌曲跨电台或线路切换时也重置校时；LRC 保留歌词中的普通方括号文字，空时间行回退纯文本，重复时间戳受 64KiB 文本预算限制。

真实服务在开发目录上通过实际 API 路径只读验证：127 个搜索候选的首批包含两条兼容 ICY 线路，均返回电台文字并解析歌手与曲名；歌词位置仍明确未知。实际广播曲目查询为未匹配，已知曲目查询返回 8 个准确身份版本，含纯文本与时间行。这些是两类独立观测，不表示每个电台都提供元数据或每首歌都有歌词。未保存或归档歌词正文，也未修改目录数据。

## 界面证据

## 发布与剩余范围

影响 API 与 Web，先 API、后 Web。不涉及任务进程、迁移、表结构、权限或环境变量；本次不需要迁移 SQL；仅对开发库执行只读查询，未执行 DDL/DML，正式库未操作，没有部署。

本阶段不包含音量统一和调台音效；识曲、产品说明、完整性能与容器交付继续推进。真实 Android/iOS 的音频输出、后台、锁屏与系统中断待设备验收。本机按用户要求不测 Docker，实际部署环境仍须验收容器、迁移与恢复。
