# ADR-0002：MySQL 与 Drizzle Kit

日期：2026-10-16。状态：已接受，待实施。取代 [ADR-0001](0001-stack-and-deployment.md) 中的数据库、驱动、文件访问及其特定运行限制。

后续状态：版本基线与通用字符配置已由 [ADR-0003](0003-table-options-and-target-environment.md) 根据实际环境修订。下文保留初始选型记录，其余工具分工继续适用。

## 背景

项目需要与 TypeScript 后端配套的关系数据库和自动化迁移方案，并在手动触发的 Jenkins 发布中执行已审核变更。当前仅有文档与工程目录骨架，尚未建立业务数据库或迁移，不涉及现存业务数据转换。

## 决定

1. 数据库采用 MySQL 8.4 LTS，业务表使用 InnoDB、utf8mb4，时间处理统一按 UTC 约定。
2. 后端使用 mysql2 连接池和 Drizzle ORM，API 与后台任务分别管理有限连接预算。
3. 结构定义采用 Drizzle MySQL Schema，SQL 与元数据由固定版本 Drizzle Kit 生成和维护。
4. Drizzle Kit 是唯一迁移执行工具；生成后 Review，在隔离 MySQL 8.4 空库和旧结构测试库验收，再随代码提交。
5. Jenkins 手动发布的独立阶段只执行已验证迁移，不在发布时生成 SQL，不直接向生产执行 `push`，不使用第二套迁移器。
6. 迁移工具环境与应用来自同一提交，单独保留 CLI、连接驱动、配置及迁移材料，连接凭据运行时注入。
7. 数据库作为独立服务管理，可使用现有实例或自管容器；API 与任务不挂载数据库数据卷。
8. 使用 MySQL 逻辑备份或经验证的服务备份机制，生产恢复前先在隔离库演练。

## 影响与约束

需要维护数据库连接、权限、连接预算、备份和 MySQL 服务健康。具体数据库服务和账户尚未配置，应用仍保持单机、API 与任务各一个实例的部署基线。

MySQL DDL 可能隐式提交，迁移失败不能视为整批已撤销。迁移前停止应用和任务写入并校验备份，失败后核对实际结构和日志，镜像回退与数据恢复分别处理。

应用读写与结构迁移使用不同权限；自动提交代码不构成数据库执行或 Jenkins 上线授权。Schema、迁移材料和发布工具的兼容性在初始化时验证。

## 验证状态

本轮仅调整选型、文档和协作规则。尚未安装驱动、启动 MySQL、生成或执行业务 SQL、创建迁移配置或运行发布；这些仍为后续实施与验收项。
