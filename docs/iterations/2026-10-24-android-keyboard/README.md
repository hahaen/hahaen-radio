# Android 输入框软键盘修复

日期：2026-10-24。

## 需求与实际变更

搜索框获得光标但手机输入法不显示，需修复并检查其他输入入口。当前应用只有三个原生文本输入入口：搜索、登录用户名和密码，均使用 `NightField`。

当前手机微信输入法在硬件按键输入后切入硬件输入模式，软键盘窗口仅 1 像素高；随后触摸 Compose 输入框时不能恢复。系统原生文本框在相同路径下可以恢复。设备操作脚本在修复前稳定失败：发送硬件按键、手指点击搜索框，键盘高度仍为 1 像素。

- 共用输入框订阅焦点和点击交互，等一个界面帧后确认实际焦点、窗口焦点与前台生命周期，再请求软键盘。
- 用户点击时补齐原生 `TextView` 同样发送的 `InputMethodManager.viewClicked` 通知，让输入法获知编辑框被点击并退出硬件输入模式。
- 此公开方法虽被弃用，但当前平台 `TextView` 仍沿用；兼容调用只发生在已聚焦的真实输入框点击后，不对任意 Compose 内容通知点击，不使用反射、强制显示或更改系统输入法设置。
- 不使用定时恢复或持续重试；主动关闭键盘后保持关闭。失焦、新交互及组件销毁取消尚未执行的请求，后台不唤起键盘。
- 导航回归同时核对可见标记和实际高度，避免将 1 像素异常判为正常；补充真实输入法的三个输入入口、硬件输入后触摸恢复、重复唤起与主动收起测试。
- 版本递增为 `0.1.0` / versionCode 4，保持应用 ID 和既有签名。

- 最终源码执行 `:app:testDebugUnitTest :app:lintDebug :app:lintRelease :app:assembleDebug :app:assembleDebugAndroidTest :app:assembleRelease` 通过（28 秒）；45 项 JVM 测试无失败。Debug / Release Lint 分别为 52 / 53 条 Warning，无 Error。
- 最终设备回归 `FieldKeyboardDeviceTest` 与 `RadioNavigationTest` 共 2 项通过（60.511 秒，包含系统界面等待）。三个输入框各两次验证触摸唤起、硬件输入后触摸恢复、输入、收起后再次唤起及主动关闭后保持关闭；搜索筛选收键盘、流派多选及返回状态保持也通过。
