# ADR-0001：技术栈、单仓库与单机部署

日期：2026-10-16。状态：已接受，待实施。

## 背景

项目需要浏览器交互、图形渲染、音频处理和数据服务。当前目标是建立可独立开发、统一发布和持续维护的工程基础，部署使用自有 Jenkins。

## 决定

1. 前后端统一使用 TypeScript，采用 pnpm Workspace 单仓库。
2. 前端选择 React 19 和 Vite 8，Three.js 与音频引擎保持独立模块。
3. 后端选择 Node.js 24 LTS 和 Fastify 5，使用 REST、Zod 和 OpenAPI 统一契约。
4. 持久化使用 SQLite、better-sqlite3 和 Drizzle；迁移文件进入版本管理。
5. 前后端独立构建与运行，使用一个域名和 Caddy 入口。
6. 基线为 Linux 单机部署；API 和任务分别作为一个实例运行。
7. 使用 Jenkins 手动触发检查、构建和部署，Docker Compose 管理服务。
8. 浏览器默认直接请求电台音频，持续音频传输不经过项目后端。

## 影响与约束

共享类型减少前后端契约偏差，运行时校验仍然必需。图形和音频模块需要显式管理资源释放，不能由界面重渲染触发重复初始化。

SQLite 简化部署，但多个写入者仍需串行写入；长事务和批处理会影响 API。数据库文件要求本机持久磁盘，备份恢复与版本发布分别管理。

Jenkins 构建节点与目标服务器可能具有不同 CPU 架构，better-sqlite3 必须在目标运行环境对应的镜像中安装与验证。

## 验证状态

目前只完成技术方案确定与文档整理。依赖组合、原生模块构建、浏览器兼容性、Jenkins 节点和实际服务器运行均待验证。

## 调整触发条件

- 需要多台服务器共同写数据库：评估 PostgreSQL 和分布式任务协调。
- 需要无持久磁盘的运行环境：重新确定数据库和部署拓扑。
- 音频需要代理或转码：独立评估资源、流量和服务边界。
- 需要改变主要框架或主版本基线：新增决策并同步相关文档。
