# 发布与回退

> 当前部署已于 2026-10-25 改为[本机编译上传与 Docker 更新](../local-upload.md)；本文中 Jenkins 配置及服务器源码路径为历史说明。


## 发布单位

前端、API、任务分别从确定提交构建和手动发布。常驻应用容器只有 `radio-api`、`radio-jobs`；前端从不可变产物镜像提取到静态版本目录，经文件摘要验证后原子切换 `web/current`，共享 Nginx 只读服务。

组件记录使用 format 2，`components.frontend/api/jobs` 分别记录实际提交、镜像及新构建的 buildNumber；`previous` 只在当前发布尚未成功时临时保护原版本。成功后 `previousVersions` 只记录上一版 SHA 和构建编号，不保留上一版产物。`schema` 单独记录实际数据库结构和对应迁移工具。备份 helper 的版本文件跟随主 API（无 API 时为任务），不能将其解释为三个组件都已更新。

## 本地镜像保留

三个组件在服务器构建后直接使用不可变镜像 ID，Compose 配置 `pull_policy: never`。构建和目标必须共用同一 Docker 引擎；本地镜像丢失时无法依赖私有仓库补拉，需要重新构建或从独立备份恢复。

按用户明确选择，各组件成功发布后只保留当前版本及配置快照，前端同时保留当前静态目录；本次操作成功之前临时保留原版本。当前结构的迁移工具始终保护。页面、静态资源、ready 与目录接口通过后，才清理本轮被淘汰的本组件历史成功版本；不清理并发构建、其他业务或全局构建缓存。其他组件的旧保留产物在其后续成功发布时分别淘汰；本次只改脚本，不立即清理服务器。清理不完整会输出固定脱敏事件，需要核对后处理，不能把删除失败说成已释放空间。

## 普通发布与迁移

无迁移时只停止/替换所选后端，前端只切换静态目录。验证所选部分后再次检查其他组件版本和健康，完成公网探针再清除 attempt。发布或健康检查失败时，在仍持有发布锁且原版本存在的情况下自动恢复原镜像/静态目录与配置、再检查可用性，构建仍报失败；恢复失败则保留 attempt 与维护状态。首次发布没有原版本时不能自动恢复。发布期间使用维护响应；单机方案不承诺无中断。

存在待迁移项时，须在隔离 MySQL 8.0.46 完成相应迁移验收，并审核混合版本兼容声明。锁内停止 API 和任务；非空库先完成一致性备份及独立存储副本校验，再使用同提交工具单次执行 Drizzle Kit。未选中的写入组件按原不可变镜像和配置快照恢复。首次空库可经明确授权初始化及同步真实目录，不能将此例外用于非空库升级。

默认契约和结构摘要必须一致。`deploy/compatibility/policy.json` 只允许经过代码/SQL Review 确认的旧契约或结构摘要，不自动推测兼容，也不使用数据库回退掩盖版本不兼容。

## 组件回退与恢复

正在失败恢复的发布使用下述 recover 入口，不使用旧构建的 Replay 重跑状态性步骤。旧流程尚保留 previous 时，仍可在完整受控源码树中显式加载主环境，以 `HAEN_DEPLOY_SCOPE=frontend|api|jobs`、`HAEN_DEPLOY_ACTION=rollback` 和 `HAEN_CONTRACT_COMPATIBILITY_CONFIRMED=true` 调用 `apps/server/src/entrypoints/deploy.ts`；入口核对实际结构并持有两层发布锁，不运行待执行 SQL。新流程成功清理后没有 previous，不能再依靠该入口即时回退。

成功发布后如需回退：

1. 从 `previousVersions` 或 Jenkins 成功构建记录取得所选组件的旧 SHA，审核它与当前其他组件、接口及数据库结构兼容；数据库结构不随应用自动回退。
2. 从当前已审核版本准备受控恢复分支，恢复所需旧应用代码及匹配依赖，保留当前发布工具并补充必要兼容声明；不要盲目执行旧 SHA 中的历史 Jenkinsfile。
3. 按正常 Review、相关测试、类型检查、构建及双远端推送流程完成恢复版本，再由用户在相应组件任务选择该分支，重新发起构建发布。
4. 核对任务结果、组件实际 SHA/构建编号及公网健康/目录检查；失败时按持久 attempt 进入下述恢复流程，不修改状态伪装成旧产物仍存在。

这种回退需要重新构建，依赖基础镜像与依赖可获取，耗时高于保留镜像的即时回退。

失败现场使用 `HAEN_DEPLOY_ACTION=recover`、`HAEN_RECOVERY_CONFIRMED=true`，明确选择 `HAEN_RECOVERY_VERSION=current|previous|attempt`。首次失败没有 current 时必须明确选择 attempt。先核对结构与记录；恢复入口要求零待迁移项。部分 DDL 失败且记录不一致时保持维护，按[正式恢复手册](../../data/backup/formal-recovery-runbook.md)处理，不能删除 attempt 或自动重跑迁移。

镜像回退不等于数据库回退。MySQL DDL 可能隐式提交；恢复旧数据库需明确恢复点和后续数据影响，禁止未经验证的逆向 SQL 或删除生产库。

## 发布报告

每次修改完成后的交付说明都要明确列出需要更新的服务或产物：前端静态资源（`radio-frontend` 发布任务）、API（`radio-api`）、后台任务（`radio-jobs`）及其他实际受影响的服务，同时说明涉及的数据库迁移、配置调整和更新顺序。无需服务更新时明确写出“本次无需更新服务”；需要更新和已经更新分别说明，实际发布按既有授权执行。

记录各组件实际提交/镜像、配置变化、SQL 执行状态、验证结果和未完成事项。已构建镜像不代表目标部署成功；以持久记录、实际容器和公网探针为准。备份见[数据文档](../../data/backup/backup-and-restore.md)，入口见[Jenkins](../jenkins/pipeline.md)。

## 协作规则更新记录（2026-10-18）

- 需求：每次修改完成后告诉用户需要更新哪些服务。
- 实际变更：在项目协作规范和本页固化交付要求，覆盖前端、API、后台任务、迁移、配置、更新顺序及无需更新的情形。
- 验证：本次仅修改文档，执行内容 Review、本地链接与目录一致性检查及差异空白检查；结果以本次交付说明为准。
- 未完成事项：无功能或部署待办。本次无需更新服务，无数据库迁移或运行配置调整。
