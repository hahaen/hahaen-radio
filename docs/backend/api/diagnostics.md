# 精简播放故障报告 API

`POST /api/v1/stations/:id/playback-reports` 接收严格 JSON `{ reportId, streamId, failure }`。电台为 UUID，线路为 24 位十六进制标识，reportId 是本次报告的随机 UUID，用于重试去重；它不是访客标识，也不放入浏览器持久存储。

failure 只允许 network、timeout、unsupported、unavailable、offline。请求体最大 512 字节；额外字段、查询参数、非 JSON 和跨站浏览器请求被拒绝。不接受自由文本、任意日志、音源 URL、音频、原始 IP 或用户代理。

新报告先验证当前目录中电台可用与线路归属，再提交仓储。服务只读取目录，不能改变电台、线路、人工屏蔽或可用状态；匿名报告始终是待核实反馈，不代表服务端已复现故障。

| HTTP | 返回 |
| --- | --- |
| 202 | accepted、reportId、电台/线路标识和 expiresAt；重复的相同有效回执返回同一记录 |
| 429 | limited 与 1–86400 秒 retryAfter；同时提供 Retry-After 响应头，不自动重试 |
| 503 | unavailable，未配置数据库、存储或目录暂不可用时降级 |
| 400 / 404 / 413 / 500 | 统一错误契约；分别包括无效/冲突回执、当前线路不匹配、超大请求或未预期错误 |

响应禁止缓存。回执号与内容冲突时拒绝，不用旧回执接受另一条故障。

## 限额、存储与保留

当前 API 全局最多一个在途操作；每分钟最多 20 次新尝试，先限流再查询目录；同一电台/线路/故障 60 秒冷却，最多 256 项内存状态。近期有效回执可直接复用，最多缓存 5 分钟且不超过记录有效期。重启可能清除短时保护，但不能重置数据库额度。

MySQL 单例行加锁后，同一事务处理去重、报告与每日额度。按数据库 UTC 时间，每日最多接受 1000 条新报告；同一有效回执不会重复扣数。10000 个固定槽位构成存储硬上限，满时覆盖旧槽位。表只含报告标识、电台、线路、固定故障、服务器收到时间与有效期。

报告有效期为收到后 7 天；摘要排除到期数据，提交也清理过期记录。独立任务在启动时和每小时清理，进程停机期间的物理删除会延后到恢复后，容量上限仍保持。清理不重置每日计数。
