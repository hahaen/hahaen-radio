# 浏览器与本地存储

## 支持策略

以主流桌面浏览器和移动浏览器为验收对象，具体最低版本在初始化时结合构建目标与实际用户设备冻结。WebGL 2、HLS、Web Audio、Media Session 和 Web Share 分别检测，不用单一浏览器名称推断全部能力。

## 本地数据

| 存储 | 用途 | 约定 |
| --- | --- | --- |
| localStorage | 少量偏好和轻量状态 | 使用命名空间、版本号和解析校验 |
| IndexedDB + idb | 较大缓存或结构化本地数据 | 设置 Schema 版本、升级和淘汰策略 |
| 内存 | 临时交互和运行状态 | 刷新后可丢失 |

本地存储可能因隐私模式、配额、用户清理或环境策略而不可用。读写失败要有可运行的内存回退，不将本地缓存当作唯一的服务器数据来源。

浏览器存储不等于账号同步。敏感凭据不放入前端构建配置或持久化偏好。

## 界面平台能力

使用 Pointer Events 统一输入，处理触摸目标、窗口尺寸变化与安全区。国际化使用 i18next；时间使用 UTC 数据和明确时区格式化。

尊重 `prefers-reduced-motion`，保持键盘导航、可见焦点和基本语义。浏览器或系统不支持的增强能力采用可解释的降级。

兼容性结果在实现后记录浏览器、系统、设备与验证范围；WebKit 自动化结果不能替代真实 iOS 音频验收。
