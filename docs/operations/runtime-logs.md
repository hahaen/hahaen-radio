# 普通进程日志与保留

API 和任务入口共用原生结构化日志目的地。生产 Compose 将二者分别写入 api_logs、jobs_logs 持久卷中的 /var/log/haen，不再保留一份 Docker local 日志。Web 和迁移继续不保存普通容器输出；数据库内的任务记录、播放报告、Jenkins 构建日志及发布/备份证据各自沿用既定规则，不混入这里。

## 默认策略

| 项目 | 已实现行为 |
| --- | --- |
| 时间 | 片段创建后七天到期；启动、打开新片段及运行中每分钟清理，包括没有新请求的时段 |
| 分段 | 每小时或达到10MiB后新建片段；单条原始输入上限16KiB，超过上限仅保留固定事件 |
| 容量 | 每个服务最多30MiB、200个文件；新建时预留完整10MiB片段，必要时先删最旧片段，因此实际保留量可能更低 |
| 权限 | 目录必须为当前运行用户所有、700；文件为600、普通文件、单链接；拒绝符号链接及未知条目 |
| 命名 | haen-毫秒时间-随机后缀.jsonl；不含地址、账号、请求参数或稳定访客标识 |
| 故障 | 创建/清理/写入失败后停止该目的地写入，输出固定runtime_log_failed事件并向自身发送SIGTERM，使用既有关闭流程；不回退保存原始输出 |

时间按UTC墙上时钟判断，目标主机应保持校时。到期删除整个片段，末尾较新的记录可能提前最多一小时删除。运行中的物理清理通常在下一分钟执行；进程停止、主机断电或被挂起时不能执行清理，恢复启动后先清理再服务，不承诺停机期间的物理删除。单服务仅一个写入进程，禁止多个实例共享同一日志卷。

新片段建立时检查磁盘与条目预算；每条日志通过同步小写入直接落到文件描述符，处理部分写入，不建立无界内存队列，也不在每次请求重新扫描目录。普通日志不逐条fsync，不作为可恢复业务状态；断电可能丢失尾部。慢磁盘会增加请求耗时，目标环境需测量磁盘延迟、容量与请求负载。

## 字段与配置

保留固定事件、UTC时间、服务名、应用提交、数字级别；请求日志可含服务端生成的requestId、HTTP方法、路由模板、响应码及耗时；任务可含固定状态与计数。剔除自由文本、异常对象、栈、SQL、配置、URL、query、请求体、请求头、IP、主机名和客户端请求标识。未知消息只保存runtime_message；不从原始文本猜测错误原因。业务排障结合固定事件、requestId和数据库内的脱敏任务状态。

HAEN_APPLICATION_REVISION由服务端镜像的VCS_REF写入，只接受完整小写提交号；本机没有版本时明确记为unversioned。API的LOG_LEVEL继续由现有Pino配置控制，任务固定事件不读取该级别。

HAEN_LOG_DIRECTORY仅供服务端读取，指定已准备的专用绝对目录；目录不存在或不安全时启动失败，不自动创建、不输出路径。生产Compose明确设置/var/log/haen，Dockerfile预建UID/GID1000、700目录，两个服务分别挂载独立命名卷。已有卷也必须满足所有权和权限，不能通过关闭校验继续启动。

本机不设置目录时输出同样经过字段投影的JSON到stdout；本机终端、人工重定向和宿主机自身的日志收集不受该文件策略管理。Jenkins/运维命令的输出沿用各自固定事件，不引入统一抓取任意stdout的收集器。创建.env.local本身不会加载变量，仍须使用现有显式env-file入口。

## 读取、更新与清理

生产docker logs不提供API/任务普通日志，排障使用docker exec在相应运行容器内以默认node用户读取最近的jsonl，不执行完整环境inspect，不复制整个卷。先列文件并按文件名排序，再按requestId/固定事件筛选需要的少量行；不将日志放进仓库、镜像、普通备份包或Jenkins归档。需要分享时再检查脱敏，局部读取不代表可以对外公开全部记录。

日志卷只存本服务片段，不能放配置、备份、标记或说明文件；清理遇到未知条目会拒绝。卷随应用重建保留，禁止使用down --volumes作为清理方式。若服务长期停用，管理员在确认进程和容器均已停止、准确核对专用日志卷后，按七天策略清理该卷，不能按相似路径批量删除。重新启用会先执行同样的过期清理。

发布顺序为审核同提交源码和镜像→隔离验收→按既有发布流程更新API/任务及Compose。没有SQL、Schema或数据库权限变更。当前镜像验收脚本已为API/任务加入独立限额tmpfs日志目录，并检查实际事件、提交与600权限；模拟Docker用例只证明命令编排。真实命名卷的首次初始化、重建保留、升级、回退和UID映射仍需目标环境验收。

服务端镜像声明io.haen.runtime-log=private-jsonl-v1能力。目标执行器在prepare中核对候选服务端镜像，缺少声明会在建立维护attempt和停写前拒绝，包括回退及保留旧服务端的仅Web更新；先升级服务端后再使用新Compose。回退候选必须包含该能力及相同Schema；不自动退回旧Docker输出策略。任务启动探针改读文件，核对服务、实际服务端提交、事件时间不早于本次容器StartedAt，避免用保留的旧启动事件冒充成功。

## 验证边界

本机测试使用真实临时文件和Fastify注入，检查安静时到期、重启清理、小时/体积分段、容量/数量上限、权限/链接拒绝、字段投影与写入故障关闭请求。时间边界使用可控时钟推进，不宣称已自然运行七天。

部署时补测真实Linux卷权限、只读根文件系统、Docker none行为、日志读取、SIGTERM与重启、磁盘满/只读/挂载丢失、自然分钟清理、时钟变化及慢磁盘负载；确认外部收集器没有另存未受控副本。Docker按用户要求留待部署环境，本机测试不等同于这些项目通过。
